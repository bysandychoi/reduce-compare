## 완료 기준 검증

1. 판별된 그룹 ID마다 독립적인 GET을 실행하며 각 응답을 별도 카드로 렌더링한다.
2. `selected`가 현재 체크 상태를, `default_selected`가 추천 복원 상태를 결정한다.
3. 각 행에 컬럼명, kind·dtype 배지, 결측률, 자동 제외 사유가 표시된다.
4. 선택 개수를 실시간으로 계산하며 0개일 때 경고를 표시하고 PUT 버튼을 비활성화한다.
5. 그룹별 선택된 컬럼명만 PUT에 전송하고 서버 응답으로 현재값과 기준값을 함께 갱신한다.
6. 추천 복원은 `default_selected`로 로컬 상태만 바꾸며 변경 여부와 저장 가능 상태를 다시 계산한다.
7. GET 오류는 그룹별 재시도를 제공하고 PUT 오류는 현재 `columns`를 변경하지 않아 편집값을 보존한다.
8. GET과 PUT 요청은 컴포넌트 해제 및 job/group 변경 때 취소되고 활성 저장 요청만 결과를 반영한다.
9. lint/build, 컬럼·그룹·업로드 API 회귀 테스트, 브라우저 실동작 검증이 모두 통과했다.

## 경계·실패 사례 검토

- 빈 컬럼: 빈 상태 문구와 최소 1개 경고가 표시되고 저장은 불가능하다.
- 추천 선택 0개: 복원 뒤에도 최소 선택 경고와 저장 차단이 유지된다.
- 동일 컬럼명/다중 그룹: input id에 group ID와 index가 포함되고 각 `ColumnGroup` 상태가 독립적이다.
- 긴 텍스트: 컬럼명과 사유는 `overflow-wrap`으로 줄바꿈되며 모바일에서는 메타 정보가 별도 행으로 배치된다.
- 중복 저장: 활성 AbortController가 있으면 추가 PUT을 시작하지 않으며 저장 중 해당 그룹 컨트롤이 비활성화된다.
- 서버 오류/정규화: 실패 시 편집값을 유지하고 성공 시 요청 추정값이 아닌 응답을 기준으로 삼는다.
- 접근성: 실제 checkbox와 연결된 label, 그룹 제목, live region, 0개 선택 alert를 제공한다. 키보드 Space 선택과 Enter 복원·저장을 확인했다.
- 보안/인코딩: job/group ID는 기존 API 계층에서 URL 인코딩되고 서버 문자열은 React 텍스트 노드로 렌더링된다.
