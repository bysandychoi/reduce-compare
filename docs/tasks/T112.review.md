# T112 adversarial review

## 검토 범위

- 후보 배치 병렬 실행, 최소 통과 크기 선택, 조기 종료
- 순차/병렬 동등성, worker 상한, threadpool 전역 설정 복원 안전성
- 처리 시간 비교와 테스트·요구사항 기록

## 검증

- batch 결과는 제출 순서(크기 오름차순)로 소비되어 완료 순서에 따라 선택이 바뀌지 않는다. 목표 통과 이후의 배치는 실행하지 않으며 worker는 최대 2로 제한된다.
- `test_search_size.py`는 실제 2-worker 동시 실행, 첫 최소 통과 후보, 이후 배치 중단, 목표 미달 시 최고 점수, 순차·병렬 curve 일치, worker 입력 경계, 동시 batch 간 threadpool 설정 context 직렬화를 확인한다.
- 순차/병렬 지표 탐색 결과는 동일했다. 100,000행 검색은 7.67초에서 2.86초로 줄었다(62.7%). 625,000행 전체 파이프라인은 60.41초 대비 46.91초였고, 크기 탐색 단계는 24.38초 대비 10.46초였다.
- `test_search_size.py`, `test_pipeline.py`, `test_metrics.py` 23 passed; Ruff, compileall, `git diff --check` 통과.
- 이전 지적: `threadpool_limits` context를 전역 잠금 안에서 실행하도록 바꾸고 동시 batch test를 추가했다. 같은 프로세스의 이 검색 경로끼리는 설정 context가 겹쳐 복구 순서가 뒤집히지 않는다.

## 잔여 한계
