## 완료 기준 검증

1. 업로드 성공 시 `GroupReview`가 작업 ID로 GET을 실행하고 응답의 모든 그룹을 렌더링한다.
2. 각 카드가 파일 경로·파일 수·컬럼 수·컬럼명·종류를 표시한다.
3. `merge` 값이 두 라디오 선택의 `checked` 상태에 직접 반영된다.
4. 현재 그룹 전체를 `{group_id, merge}`로 매핑해 단일 PUT에 전송한다. 변경이 없거나 요청 중이면 중복 실행하지 않는다.
5. 저장 중 fieldset과 저장 버튼이 비활성화되며 성공 응답으로 그룹과 기준값을 함께 교체한다.
6. GET 오류는 재시도 버튼을 제공하고, PUT 오류는 현재 `groups`를 변경하지 않아 편집값을 유지한다.
7. GET은 effect 정리 시 취소되고, PUT은 컴포넌트 해제 시 취소된다. 활성 저장 요청과 일치하는 응답만 반영한다.
8. lint/build, 관련 API 테스트, 브라우저 실동작 검증이 모두 통과했다.

## 경계·실패 사례 검토

- 빈 그룹: 빈 상태 문구만 표시되고 PUT 버튼은 숨겨진다.
- 빈 컬럼·긴 경로: 빈 목록을 안전하게 렌더링하고 경로는 `overflow-wrap`으로 줄바꿈한다.
- 다중 그룹: `group_id`별 독립 radio name을 사용하며 PUT에는 모든 그룹이 한 번씩 포함된다.
- 느린/실패 요청: 로딩·저장 상태가 중복 요청을 막고, AbortError는 사용자 오류로 표시하지 않는다.
- 서버 정규화: PUT 성공 뒤 요청값이 아닌 서버 응답을 새 기준으로 삼는다.
- 접근성: 그룹별 fieldset/legend, 라디오, 파일·컬럼 목록의 접근 가능한 이름, live region을 제공한다. 키보드 Space 전환과 Enter 저장을 실제 브라우저에서 확인했다.
- 작은 화면: 카드 헤더와 저장 영역이 세로 배치되고 선택 컨트롤은 전체 폭을 사용한다.
- 보안/인코딩: 작업 ID는 기존 API 계층에서 URL 인코딩되고, 렌더링 문자열은 React 텍스트 노드로 출력된다.
