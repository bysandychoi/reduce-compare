- Task definition and `docs/tasks/T061.md`

- Ruff, 63-test backend suite, frontend lint/build, diff checks, and line counts

## Acceptance review

1. **Grouping:** PASS. Same ordered columns group together; different schemas remain separate.
2. **Response detail:** PASS. Deterministic IDs, relative files, column classification metadata, and merge flags are returned without absolute paths.
3. **User changes:** PASS. PUT saves complete merge decisions and subsequent GET applies them.
4. **Invalid jobs/data:** PASS. Invalid or missing jobs return 404; no readable tables and parse failures return 422.
5. **Update validation:** PASS. Duplicate, unknown, or missing group IDs are rejected before persistent state is replaced.
6. **Quality gates:** PASS. Ruff, 63 backend tests, frontend lint/build, whitespace checks, and the 200-line router limit passed.

## Adversarial checks

- Job IDs accept only the 32-character lowercase hexadecimal format generated by T060, preventing path traversal.
- Uploaded files are collected only beneath the resolved job upload directory.
- Non-tabular text is skipped through the existing ingestion contract.
- Malformed, empty, undecodable, or unreadable tables become client validation failures rather than unhandled parsing errors.
- Deterministic sorting from the core grouping layer stabilizes `group-N` identifiers while immutable uploads remain unchanged.
- PUT requires the exact current group set, preventing stale clients from silently dropping newly detected groups.
- State is written to a sibling temporary file and atomically replaced only after full validation.
- Rejected updates do not create or overwrite `groups.json`.
- Saved state contains only booleans keyed by known group IDs and API output contains no server filesystem paths.
- Group calculation reads only schema samples rather than loading full large files.
