## 이전 발견 해결 확인

- 최초 리뷰의 P1은 컬럼 API가 전체 프레임에서 층화 기준을 계산해 실제 파이프라인과 달라질 수 있다는 문제였다.
- 수정 후 API는 현재 저장 선택 컬럼의 결측 행을 `drop_missing_rows`로 제거한 프레임에서 기존 `choose_stratify_column`을 호출한다.
- 행 제거 전에는 `a`, 제거 후에는 `b`가 더 고르게 분포하는 회귀 데이터로 응답이 `b`인지 확인했다.
- 저장 전 로컬 편집은 부정확한 이름을 예측하지 않고 재계산 예정과 현재 저장 기준을 구분해 표시한다.

## 완료 기준 검증

1. 각 그룹은 로딩·오류·0개 선택·미저장 변경·저장 중이면 `ready=false`를 보고한다. 전체 상태는 모든 현재 그룹이 ready일 때만 완료다.
2. 0개 선택 시 경고, PUT 버튼 비활성, 전체 실행 불가 안내가 함께 표시된다.
3. 저장된 현재 선택은 실제 파이프라인과 동일한 결측 제거 및 T029 함수로 층화 기준 이름 또는 `없음`을 반환한다.
4. 편집 중에는 재계산 예정 상태, PUT 성공 후에는 서버 응답의 정확한 층화 기준을 표시한다.
5. readiness key에 job ID와 그룹 ID 집합을 포함해 작업·그룹 변경 때 이전 준비 상태를 재사용하지 않는다.
6. `onReadyChange` 콜백으로 후행 T075 실행 UI가 실행 가능 여부를 소비할 수 있다.

## 경계·실패 사례 검토

- 범주형 없음/범주 수 범위 밖: 정상적으로 `없음`을 표시하며 숫자형만 저장한 그룹도 실행 준비 가능하다.
- 빈 선택: 서버 PUT 전에 프론트에서 차단되고 경고가 접근성 alert로 노출된다.
- 결측 분포 변화: 추가 회귀 테스트가 전처리 전후 후보 역전을 검증한다.
- 다중 그룹: 그룹별 effect가 독립 상태를 보고하고 하나라도 false면 전체 ready가 false다.
- 요청 실패·지연: 기존 T076 AbortController와 오류 상태가 유지되며 오류 그룹은 ready가 될 수 없다.
- 보안/인코딩: 식별자는 기존 API 계층에서 인코딩되고 컬럼명은 React 텍스트 노드로 표시된다.
