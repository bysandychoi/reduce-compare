# T112 — 크기 탐색 병렬화/조기 종료

## 작업 분석

- 백로그 기준: `todo`, E11, 예상 30분. 의존 T110(`done`).
- 완료 기준: 크기 탐색 시간 단축 측정 결과 기록.
- 관련 요구: [problem.md §8](../../problem.md)의 50만 행 2분 목표.
- 현재 코드: `search_size`는 후보 크기를 순차 평가하며 기준 점수에 도달하면 즉시 중단한다. 후보는 작은 순서라 현재 조기 종료는 최소 통과 크기를 보장한다. T110 측정에서 625,000행 전체 파이프라인 63.33초 중 크기 탐색 단계는 25.04초였다.
- 범위: 탐색 후보를 작은 배치(최대 2개)로 병렬 평가하고 각 배치 사이 조기 종료한다. 후보 순서상 첫 목표 통과 결과를 선택해 순차 실행과 동일한 의미를 유지하며, 불필요한 대규모 동시 작업은 피한다. 기준 구현과 개선 구현 시간을 같은 데이터/seed/target에서 비교한다.
- 비목표: 탐색 점수나 후보 생성 공식 변경, 방식 비교 병렬화, API 진행률 변경, 대규모 무제한 worker 풀.
- 완료 기준: 병렬/순차 결과 선택과 size curve 의미 일치 테스트, 잘못된 worker 수 처리, 기존 결과와 비교 가능한 실제 탐색 시간 단축 측정. 개선이 측정되지 않거나 메모리 위험이 크면 병렬화를 기본 경로로 두지 않는다.

## 관련 파일 및 검증

- `backend/app/core/pipeline.py`: `search_size`, `size_candidates`, 기존 `run_once`.
- `backend/tests/test_pipeline.py` (또는 새 검색 테스트): 병렬 결과 순서, 첫 통과 후보 선택, no-hit 최대 점수 및 worker 경계.
- `scripts/benchmark.py --rows 100000` 및 동일 폴더를 사용한 순차/병렬 검색 비교.
- 검증: 지표·파이프라인 테스트, Ruff, compileall, 동등한 결과와 시간 비교.

## 위험과 경계

- 각 후보는 KMeans/지표 계산과 큰 원본 메타데이터를 만드므로 동시 실행 수를 제한하고 메모리 급증을 확인한다.
- 병렬 결과는 완료 순서로 반환하면 안 된다. 반드시 후보 크기 오름차순으로 목표 통과를 판정한다.
- 배치 내 더 큰 후보가 작은 후보와 함께 계산될 수 있으므로 제한된 추가 비용을 기록한다.
- 스레드 네이티브 라이브러리의 내부 병렬 처리와 중첩되어 느려지지 않도록 측정한다.

## 구현 및 검증 결과

- `search_size`는 기본 worker 2로 후보를 최대 2개씩 평가하며, 각 배치 결과를 후보 크기 순으로 판정한다. 첫 기준 통과 후 다음 배치를 시작하지 않는다. worker 범위는 1~2로 제한하고 수치 라이브러리 내부 스레드를 batch 안에서 1개로 제한해 중첩 병렬화를 피한다. process-wide threadpool 설정 context는 전역 잠금으로 동시 검색 간 교차 복원을 막는다.
- 동일한 100,000행 합성 입력 및 seed/target으로 두 스키마 그룹 크기 탐색 비교:

| 실행 | 탐색 시간 | 평가 후보 수 | 결과 (크기, 점수) |
| :--- | ---: | :--- | :--- |
| 순차 (`workers=1`) | 7.67초 | 2, 1 | (283, 88.3), (150, 92.0) |
| 병렬 (`workers=2`) | 2.86초 | 2, 1 | (283, 88.3), (150, 92.0) |

- 이 측정에서 탐색 시간은 62.7% 줄었고, 최종 후보/점수는 동일했다.
- 500,000행 요청(실제 전체 625,000행) 전체 벤치마크: 파이프라인 46.91초, 크기 탐색 10.46초. 순차 기준 실행(T111) 60.41초/24.38초 대비 전체 22.3%, 크기 탐색 57.1% 단축.
- 검증: `test_search_size.py`, `test_pipeline.py`, `test_metrics.py` 총 23 passed; Ruff, compileall 통과. 동시 배치가 threadpool 설정 context에 한 번에 진입하는지도 회귀 테스트로 확인한다. 실측은 합성 데이터 생성과 브라우저 UI를 제외한다.
