# T016 백로그 대시보드 문서 그림 표시

| 항목 | 값 |
|---|---|
| 에픽 | E1 프로젝트 셋업 |
| 예상 | 20분 |
| 선행 | 없음 |
| 후행 | 없음 |

## 쉽게 말하면
백로그 대시보드에서 안내서(docs/tasks/<ID>.md)를 열면 마크다운 안의 이미지(`![alt](경로)`)가 표시되지 않습니다. 마크다운 렌더러에 이미지 파싱 기능을 추가하고, docs/tasks 폴더의 이미지 파일을 상대 경로로 찾아 표시하면 이 문제가 해결됩니다. T139.md와 T141.md의 concept.png 같은 다이어그램이 보일 수 있게 됩니다.

## 해야 할 일
- [x] renderMarkdown() 함수에 `![alt](path)` 이미지 구문 파싱 추가
- [x] 파싱한 이미지를 `<img>` 요소로 변환하여 마크다운 DOM에 삽입
- [x] loadDocsFileList()에서 docs/tasks 폴더 내 파일 목록을 유지해서 상대 경로 해석에 사용
- [x] 상대 경로(예: T139/concept.png) 해석 및 보안 처리: 외부 URL와 상위 경로(../) 차단
- [x] 이미지를 blob: URL(URL.createObjectURL, 폴더 재연결 시 해제)로 표시하고 크기 제한 (패널 폭 초과 방지)

## 완료 기준
- [x] docs/tasks 폴더 연결 후 T139.md·T141.md의 concept.png가 안내서 보기에서 표시된다
- [x] 하위 폴더 상대 경로(T139/concept.png)와 ./ 접두 경로를 해석한다
- [x] 찾을 수 없는 이미지는 alt 텍스트와 경로로 표시되고 외부 URL·상위 경로(../)는 불러오지 않는다
- [x] 이미지가 패널 폭을 넘지 않는다

## 관련 문서
문제 요구사항에서 이미지 표시 기능이 직접 명시되지 않음. T139·T141에서 개념 다이어그램이 필요하다고 문서에 명시됨.

## 관련 파일
| 파일 | 상태 | 이유 |

| docs/tasks/T139.md | 있음 | 18행에 ![상관 0과 측정 불가의 차이](T139/concept.png) 참조 |

## 줄 수 한도
- scripts/backlog_dashboard.html: HTML 파일로 line_limits 규칙 없음 (현재 1048줄). 필요시 리뷰 단계에서 함수 분리 검토.

## 주의할 점
- 마크다운 렌더러가 외부 라이브러리 없이 기본 기능만 지원하므로, 이미지 파싱도 정규식 기반으로 간단히 구현해야 함
- FileReader API의 readAsArrayBuffer()와 Blob을 사용해서 바이너리 이미지를 data: URL로 변환 (base64 인코딩)
- 상대 경로는 docs/tasks 폴더 기준으로 해석: T139/concept.png → docs/tasks/T139/concept.png
- T141.md는 T139/concept.png를 참조하므로 동일한 이미지 사용
- state.docFiles와 state.reviewFiles를 활용해 현재 로드된 파일 목록에서 이미지를 검색
- 이미지 요소에 max-width 스타일 적용 (예: max-width: 100% 또는 패널 폭의 90%)
- 찾을 수 없는 이미지: <img> 대신 "[이미지를 표시할 수 없음: alt_text (경로)]" 같은 텍스트 또는 회색 placeholder 박스로 표시
