## Acceptance review

1. **Same-origin frontend request:** PASS. React requests `/api/health` without a backend host embedded in application code.
2. **Development proxy:** PASS. Vite rewrites the leading `/api` prefix and forwards to `127.0.0.1:8000`.
3. **Connected state:** PASS. A valid health payload displays the backend version.
4. **Loading/failure states:** PASS. All three connection states have visible text in an ARIA live status region.
5. **Frontend quality checks:** PASS. ESLint and the Vite 8 production build completed successfully.
6. **Live integration:** PASS. With both servers running, `GET http://127.0.0.1:5173/api/health` returned HTTP 200 and `{"status":"ok","version":"0.1.0"}`.

## Adversarial checks

- Backend unavailable or non-2xx: caught and represented as unavailable without hiding the rest of the page.
- Malformed JSON or wrong response shape: rejected by the response guard and represented as unavailable.
- Empty version: accepted as a string; the backend contract currently guarantees the package version, and no security or correctness boundary depends on it.
- React Strict Mode: effect cleanup aborts the superseded request and ignores the expected abort error.
- Stale state after unmount: the abort signal prevents normal fetch completion after cleanup.
- Proxy scope: only the leading `/api` substring is rewritten; unrelated path content is unchanged.
- CORS/security: browser requests remain same-origin and no permissive backend CORS middleware was introduced.
- Accessibility: connection changes use `role="status"` and `aria-live="polite"`; colored dots are decorative and status is also conveyed in text.
- Encoding: Korean UI text is compiled and served as UTF-8.
- Production boundary: the review does not claim the development proxy works in a static production deployment; that topology is outside T013.
- Performance: a single lightweight startup request is issued, with no polling or heavy dependency added.
