## 목표

그래프 설정의 종류·기본값·허용 범위·적용 그래프를 데이터로 정의합니다. T101은 이 스키마만 순회해 컨트롤을 만들 수 있어야 하며, 새 설정은 UI 조건문 수정 없이 정의 한 건 추가로 노출되어야 합니다.

## 범위

- `range`, `color`, `select`, `boolean` 설정 정의를 판별 가능한 TypeScript union으로 만든다.
- 모든 정의에 key, label, 설명, 기본값, 적용 graph 종류를 둔다.
- range의 min/max/step, select의 option 값/라벨을 타입별 필수 정보로 둔다.
- schema에서 기본 설정 객체와 특정 graph의 정의 목록을 만든다.
- 외부/저장 설정을 schema 기준으로 정규화해 누락·잘못된 값을 기본값으로 되돌린다.
- 후속 UI가 읽을 색상·점 크기·투명도·네트워크 배치·범례 정의를 등록한다. T102~T105는 이 값을 실제 그래프에 연결한다.

## 비범위

- 설정 패널 UI(T101), 실제 그래프 반영(T102~T105), 초기화 버튼(T106)
- localStorage·서버 저장과 프리셋 저장/불러오기(v1 범위 밖)

## 완료 기준

- [x] 네 설정 타입이 잘못된 필드 조합을 TypeScript에서 허용하지 않는다.
- [x] key와 select option 값이 중복되지 않고 기본값이 범위/옵션 안에 있다.
- [x] 특정 graph에 적용되는 정의만 안정된 schema 순서로 조회된다.
- [x] 기본값 객체 생성과 unknown 저장값 정규화가 boolean/color/select/range에 동작한다.
- [x] 새 정의는 schema 배열에 추가하는 것만으로 조회·기본값·정규화 대상이 된다.
- [x] 프런트 lint/build가 통과하고 파일·함수 한도를 지킨다.

## 설계

- graph 식별자는 현재 GraphExplorer 종류와 동일한 문자열 union으로 공유한다.
- color는 `#RRGGBB`, range는 유한 수이면서 min~max 및 step 격자, select는 options 값, boolean은 실제 boolean만 인정한다.
- 알 수 없는 key는 결과에서 버려 과거/미래 버전 설정이 현재 렌더러에 침투하지 않게 한다.
- 정규화는 입력 객체를 변형하지 않고 모든 schema key가 채워진 새 객체를 반환한다.

## 테스트와 경계

- NaN/Infinity, 범위 밖, step 불일치, 잘못된 hex, 없는 select 값, truthy 문자열
- null·배열·원시값 입력과 알 수 없는 key
- schema key/option 중복 및 잘못된 기본값은 모듈 로딩 시 명확히 실패

## 줄 수 한도

- `frontend/src/**/*.ts`: 파일 200줄, 함수 50줄
- `frontend/src/**/*.tsx`: 파일 250줄, 함수 80줄

## 시각 샘플

이 태스크는 화면이 아니라 설정 데이터 계약만 정의하므로 시각 샘플 대상이 아니다. 실제 설정 패널은 T101에서 제공한다.

## 구현 결과

- 현재 schema에는 원본/축소본 색상, 점 크기, 투명도, 네트워크 배치, 범례 표시가 정의돼 있다.
- 모듈 로딩 시 key·graph·range·select option·기본값을 검증해 잘못된 schema를 즉시 실패시킨다.
- UI가 빈 컨트롤을 만들지 않도록 key·label·description과 select option 값·라벨의 공백 문자열도 거절한다.
- `normalizeGraphSettings`는 잘못된 hex, step에 맞지 않는 수, 없는 select 값, truthy 문자열을 기본값으로 복구하고 알 수 없는 key를 제거한다.
- Node의 TypeScript strip 실행으로 네 타입의 유효/무효 값과 network 적용 목록을 확인했다.
- 프런트 lint와 production build가 통과했다.
