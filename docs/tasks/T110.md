# T110 — 처리 시간 측정 스크립트

## 작업 분석

- 백로그 기준: `todo`, E11, 예상 25분. 의존 T015(`done`), T054(`done`); 후행 T111/T112.
- 요구사항: [problem.md §8](../../problem.md) — 50만 행에서 업로드부터 결과 화면까지 2분 이내. T110의 완료 기준은 입력 규모별 단계 시간 리포트 출력이다.
- 범위: CLI 벤치마크로 1만/10만/50만 행 입력을 측정하고 단계별 경과 시간 및 총 처리 시간을 표와 JSON으로 출력한다. 기존 샘플 생성기를 활용해 재현 가능한 합성 CSV를 만들 수 있게 한다.
- 비목표: 파이프라인 최적화, API/UI 진행률 변경, 사용자 데이터의 기본 저장, 성능 목표 달성 주장. 측정 결과는 실행한 머신·환경에 한정한다.
- 판정 기준: 세 규모의 단계별 시간 리포트 출력; 50만 행 파이프라인 시간과 120초 목표의 차이를 명시; 잘못된 행 수/입력 경로를 분명히 거부하고 임시 생성 데이터는 실행 종료 후 정리.

## 현재 구조와 구현 계획

- `scripts/make_sample_data.py`는 지정 행 수의 혼합 CSV와 별도 스키마 파일을 생성한다.
- `backend/app/core/ingest.py`, `schema.py`, `prepare.py`, `pipeline.py`가 폴더 탐색/스키마 판별/병합·전처리/크기 탐색·방식 선택·투영 단계를 제공한다.
- 구현: `scripts/benchmark.py`에서 단계 함수를 계측하며 프로덕션 파이프라인 코드는 수정하지 않았다. 기본 실행은 1만/10만/50만 그룹 A 행을 생성해 측정하며 `--folder`로 실제 폴더, `--json`으로 환경 정보와 상세 결과를 저장할 수 있다.
- 데이터 생성 시간은 측정 구간 밖이다. 입력 탐색부터 투영까지를 `total_pipeline`으로 기록하고 텍스트 표와 JSON에 요청 행/총 폴더 행, 단계별 시간, 건너뛴 그룹, 120초 기준 판정을 포함한다. 생성 데이터는 임시 디렉터리에서 자동 삭제된다.

## 검증 계획 및 위험

- CLI 도움말, 잘못된 입력, 단계 누락 없는 JSON/텍스트, 임시 폴더 정리를 확인한다.
- 스크립트 구문 검사와 Ruff 실행.
- 50만 행 단계에서 메모리 사용량이 커질 수 있고 알고리즘 입력 크기에 따라 2분을 크게 넘을 수 있다. 제한된 환경의 측정은 목표 달성 증거가 아니며 CPU/메모리/Python 및 패키지 버전을 같이 기록한다.
- 폴더 입력 모드와 생성 모드 간 의미 차이를 리포트에서 구분한다. 파일 수 또는 그룹별 실패가 있으면 총 시간에 반영하되 보고서에 실패도 남긴다.

## 구현 및 검증 결과

- 측정 환경: Windows 11, Python 3.12.14, 논리 CPU 18개. 합성 샘플 기본 seed 7, 기본 유사도 목표 85.
- 실행 결과 (합성 CSV 생성 시간 제외, 폴더 탐색부터 투영까지):

| 요청→실제 전체 행 | 탐색·스키마 | 병합·전처리 | 크기 탐색 | 방식 비교 | 투영 | 총 파이프라인 | 목표 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: | :--- |
| 10,000→12,500 | 0.13초 | 0.06초 | 2.54초 | 6.81초 | 0.01초 | 9.54초 | 120초 이내 |
| 100,000→125,000 | 0.16초 | 0.36초 | 8.56초 | 15.23초 | 0.02초 | 24.33초 | 120초 이내 |
| 500,000→625,000 | 0.16초 | 1.76초 | 25.04초 | 36.35초 | 0.03초 | 63.33초 | 120초 이내 |

- 별도 최소 규모 재실행: 10,000 → 12,500행, 9.78초. 시간 차이는 실행 환경 변동으로 본다.
- 검증: Ruff 통과, `compileall` 통과, `--help` 확인, JSON 보고서와 환경 메타데이터 출력 확인, 0행 거부, 없는 입력 폴더 거부 확인. 보고서 경로가 입력 CSV와 겹치는 경우 종료 코드 2로 거부하고 원본 SHA-256이 유지되는지 확인; 별도 보고서 저장은 유효 JSON으로 확인.
- 범위 한계: 이 수치는 브라우저 업로드/렌더링과 CSV 생성 시간을 포함하지 않아 제품 요구사항의 “업로드부터 결과 화면까지” 전체 검증은 아니다. 완료된 성능 개선이나 목표 달성을 보장하지 않는다.

## 해석상 주의

- 요청 행 수는 그룹 A 기준이다. 생성기는 별도 스키마 그룹 B도 추가하므로 실제 파이프라인 전체 행 수가 더 많다.
- 단계별 시간은 그룹 간 누적값이며 총 시간과 작은 차이가 날 수 있다. 생성·브라우저 업로드·결과 렌더링 시간은 포함하지 않는다.
