## Scope

- Confirm the backend dependency manifest includes FastAPI, Uvicorn, and the data-processing dependencies required by the backlog item.
- Confirm the backend exposes a FastAPI application that can be launched with Uvicorn.
- Confirm `GET /health` returns HTTP 200 and a stable health payload.
- Add or adjust the smallest backend files and tests needed to satisfy those checks.
- Run available lint, compilation, and health endpoint tests.

The repository already contains an implementation in `backend/`; this task will validate that implementation and only repair gaps against the acceptance criteria.

## Non-goals

- Implementing upload, ingestion, sampling, metrics, or other product APIs.
- Adding frontend integration or CORS policy.
- Introducing deployment, authentication, persistence, or container configuration.
- Committing a local virtual environment.
- Upgrading or pinning every dependency beyond what is required for initialization.

## Acceptance criteria

1. The dependency manifest covers `pandas`, `numpy`, `scikit-learn`, `umap-learn`, `scipy`, `fastapi`, and `uvicorn`.
2. Uvicorn can import and start `app.main:app` from the `backend` directory.
3. `GET /health` returns HTTP 200.
4. The endpoint response is deterministic and suitable for a local readiness check.
5. Backend lint/compilation and the focused health test pass in the available environment.
6. A final local verification after `pip install -r requirements.txt` remains required if package installation or server startup is blocked in this environment.

## Relevant requirements

- `problem.md` §2: the product runs locally as a browser-accessed web application and needs no authentication or deployment.
- `problem.md` §8: heavy computation belongs in a local backend; FastAPI is the suggested backend stack.
- `problem.md` §8: the eventual system should process 500,000 rows within two minutes. T011 only establishes the service boundary and does not benchmark processing.

## Existing and expected files

- `backend/requirements.txt`: backend runtime and development dependencies.
- `backend/pyproject.toml`: project metadata plus Ruff and pytest configuration.
- `backend/app/__init__.py`: package version.
- `backend/app/main.py`: FastAPI application and health route.
- `backend/tests/test_health.py`: focused endpoint test.

No additional application file is expected unless verification exposes a gap.

## Test plan

- Run `ruff check .` from `backend`.
- Run Python bytecode compilation for the backend package and tests.
- Run `pytest tests/test_health.py` from `backend`.
- If Uvicorn and dependencies are available, start the application locally and request `/health` over HTTP.
- If dependencies cannot be installed because package-network access is unavailable, record that limitation and retain the backlog's required local verification.

## Edge cases and risks

- Missing FastAPI/TestClient dependencies can prevent the focused test from collecting.
- An import path that works only from the repository root may fail when Uvicorn is launched from `backend`; verification must use the documented working directory.
- The health route must not depend on data files, network access, or application state.
- Windows console encoding may affect tooling output but must not affect the HTTP payload.
- A version mismatch between package metadata and the health response would make diagnostics misleading.
