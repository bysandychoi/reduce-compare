## Findings

1. **P1 — Unexpected worker exceptions still expose internal details and absolute paths.** `backend/app/api/runs.py:51` copies the first 300 characters of every exception into `run.json`, and both status and result APIs return it. Reproduce by monkeypatching `run_folder_pipeline` to raise `RuntimeError(r"failed at C:\\private\\input.csv")`; the private path is returned verbatim. This conflicts with the task goal of replacing internal errors with user-facing messages and with the analysis risk that exception strings may contain local paths. Preserve actionable messages only for known validation exceptions; map unexpected and I/O exceptions to stage-specific safe reasons, and add a regression test.

2. **P2 — Unicode failures take the generic `ValueError` branch before the intended safe branch.** `backend/app/api/groups.py:75` catches `ValueError` before `UnicodeError`, but `UnicodeError` inherits from `ValueError`. A decoding exception can therefore expose its raw codec payload/path, while the safe `파일 인코딩을 읽을 수 없습니다` branch at line 78 is unreachable for that class. Catch `UnicodeError` first and add a focused test that forces schema extraction to raise it.
