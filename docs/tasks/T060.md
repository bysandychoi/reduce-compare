# T060 Task Analysis — 폴더 업로드 API

## Task and dependency status

- Task: T060, 폴더 업로드 API
- Status: `todo` at analysis time; must move to `in_progress` before application changes.
- Estimate: 25 minutes
- Dependencies: T011 (`done`), T020 (`done`)
- Downstream task: T061
- Active branch: `dev`

## Scope

- Add `POST /jobs` accepting multiple uploaded tabular files as multipart form data.
- Generate a collision-resistant job ID and persist accepted files beneath an ignored temporary job directory.
- Preserve safe relative folder structure where the browser supplies it.
- Reject requests with no accepted CSV/TSV/table-text file.
- Return the job ID and accepted file metadata needed by the next job-processing task.
- Register the router in the FastAPI application and add focused API tests.

## Non-goals

- Parsing file contents, schema extraction, grouping, reduction, or background processing.
- Job status, cancellation, progress, result, or deletion endpoints.
- Persistent database records or restart recovery.
- Authentication, quotas, or remote/cloud storage.
- Frontend upload UI.

## Technical approach

- Create a dedicated API router under `backend/app/api/`.
- Store jobs under `tmp/jobs/<uuid>/uploads`, which is already ignored by Git.
- Accept extensions supported by the existing ingest layer: `.csv`, `.tsv`, and `.txt`.
- Normalize upload names, reject absolute paths and traversal segments, and prevent duplicate-path overwrite.
- Stream uploads to disk in bounded chunks rather than loading entire files into memory.
- Remove a partially created job directory if validation or writing fails.

## Acceptance criteria

1. `POST /jobs` with one or more accepted files returns HTTP 201 and a `job_id`.
2. Accepted files are saved under that job's temporary upload directory with their content intact.
3. Multiple files and safe relative paths are supported without overwriting one another.
4. Unsupported-only or empty upload lists return a clear 4xx response and leave no job directory.
5. Absolute paths, traversal paths, and duplicate target paths are rejected.
6. Focused API tests, the full backend suite, Ruff, and frontend regression gates pass.

## Relevant requirements

- `problem.md` §3: input unit is a folder containing CSV, TSV, and delimited text files.
- `problem.md` §3: non-tabular text is skipped later by ingestion; T060 performs extension-level receipt only.
- `problem.md` §7: the browser selects/uploads a data folder before automatic analysis.
- `problem.md` §8: inputs may contain hundreds of thousands of rows, so upload handling must be streamed.

## Existing and expected files

- `backend/app/api/jobs.py`: new jobs router and upload persistence.
- `backend/app/main.py`: include the jobs router.
- `backend/tests/test_jobs.py`: focused request, persistence, filtering, and path-safety tests.
- `backend/app/core/ingest.py`: existing supported suffix definitions; reuse without changing ingestion behavior.
- `tmp/`: ignored runtime storage, created only when requests arrive.

## Test plan

- Run the task guard before mutations.
- Test single and multiple file uploads and verify bytes on disk.
- Test relative folder paths, unsupported-only input, traversal, absolute paths, and duplicate names.
- Isolate storage in tests through dependency/configurable root override.
- Run Ruff and all backend tests.
- Run frontend lint/build as regression checks.

## Edge cases and risks

- Upload filenames are untrusted and may contain `..`, absolute paths, Windows separators, or drive prefixes.
- Two parts may resolve to the same destination and silently overwrite unless rejected.
- Failed writes can leave partial job state unless cleanup is guaranteed.
- Large files must not be read fully into memory.
- Empty accepted files are valid at receipt time; content validation belongs to ingestion tasks.
- Concurrent requests need independent UUID directories.
