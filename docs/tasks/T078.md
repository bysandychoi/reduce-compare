## 주의할 점
- **seed와 lot 다양성**: 단위 컬럼 limit(예: lot_id=100)이 있을 때, `--limit-mode sample`을 쓰면 seed마다 `pick_unit_values`에서 다른 lot을 뽑는다. 이를 통해 각 세트가 서로 다른 lot 조합을 대표하게 된다.
- **시도 상한과 수집 조건**: `--max-tries`에 도달해도 기준을 넘는 세트가 N개 미만이면 모은 만큼 저장하고 메시지에 "시도 \<MAX-TRIES\>회 한도, 세트 \<M\>개 모음"으로 알린다.
- **--limit 도움말 수정**: T069 리뷰 2 지적 3에서 단위 컬럼이 여러 개일 때 마지막 컬럼만 개수를 정확히 보장한다고 명확히 했으므로, 도움말도 그에 맞게 수정해야 한다.
- **T069와의 연계**: T069에서 단위 컬럼 limit의 적용 방식과 순서를 정했으므로, 이를 T078의 seed 반복 로직에 그대로 적용한다.

## 작업 기록
- `scripts/units_sets.py`(새 파일): `make_sets`가 seed를 `--seed`부터 1씩 올리며 축소 → 점수 `--target` 미만은 버리고, 선택 행 집합(sha1)이 같은 세트도 버림 → `out/sets_<그룹>/set_###.csv`(첫 컬럼 `_weight`)와 요약표 `out/sets_<그룹>.csv`(set, seed, rows, units, total, columns, combos, unit_size, file). 시도 상한 `--max-tries`(기본 세트 수×20)에 닿으면 모은 개수·이유를 출력. 0개여도 요약표 헤더는 남김.
- 단위 컬럼 limit이 있으면 세트마다 `pick_unit_values(mode="sample", seed=…)`로 lot을 원본 비율 확률로 다시 뽑고(행 필터 eqp/mask 결과는 본 실행과 같음), 없으면 본 실행에서 쓴 단위 비율(--ratio 또는 자동 탐색 결과)로 `stratified_units`.
- `run_reduce_units.py`: `--sets`, `--max-tries` 추가, `reduce_group`이 쓴 비율을 함께 돌려줌, `--limit` 도움말을 "단위 컬럼이 여러 개면 마지막 컬럼 개수만 정확"으로 수정(T069 리뷰 2 사소).
- 성능: 세트 하나에 ~10초 걸려 100세트가 수십 분이었다. 원인은 `grouped.combo_key`의 행별 `agg(SEP.join, axis=1)`(1.8만 행에 1초, 세트당 6회). 결측이 없으면 열 단위 문자열 연결로 바꿔 결과 문자열은 동일(테스트로 확인), 세트당 0.5초. 결측이 있으면 기존 경로 유지(결측 처리는 T068).
- 확인: 600 lot 합성 데이터 `--ratio 0.2 --sets 100 --target 80` → 100개, 58초, 점수 96.9~98.5, 모두 서로 다름. `--limit lot_id=100,eqp_id=30 --sets 20` → 세트마다 lot 100개, 서로 다른 20세트. `--target 99.9 --max-tries 15` → 0개 저장과 상한 안내.
- 테스트: `backend/tests/test_unit_sets.py` 4건. pytest 210 passed.

- 중요 2(서로 다른 세트를 더 못 만드는 경우):
  - 미리 판별: `--ratio 1.0`이거나 단위 컬럼 limit이 남은 값 수 이상이면 "서로 다른 세트를 만들 수 없습니다 — 이유"를 알리고 1개만 만든다.

  - 본 실행 점수가 --target 미만이면 세트 만들기 전에 경고.
- 사소: `--sets < 0`, `--max-tries < 1`은 인자 오류(`--max-tries` 기본값 판정은 `is None`). `combo_key`가 같은 컬럼을 두 번 받아도 위치로 꺼내 이전과 같은 Series를 돌려줌.
