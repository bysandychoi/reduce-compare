# T013 Task Analysis — 프론트-백엔드 연결 설정

- Task: T013, 프론트-백엔드 연결 설정
- Status: `todo` at analysis time; must move to `in_progress` before application changes.
- Estimate: 15 minutes
- Dependencies: T011 (`done`), T012 (`done`)
- Downstream tasks: T014, T071
- Active branch: `dev`

## Scope

- Configure the Vite development server to forward frontend API requests to the local FastAPI server.
- Call the existing backend `/health` endpoint from the React application through a same-origin frontend path.
- Display loading, connected, and unavailable states in the initial page.
- Keep the connection code independent of later upload and job APIs.
- Verify lint, production build, both local servers, proxy forwarding, and rendered-source wiring.

## Non-goals

- Adding new backend endpoints or changing the health response.
- Production deployment or serving the frontend from FastAPI.
- Authentication, retries, polling, global API clients, or state-management libraries.
- Implementing upload, jobs, results, routing, or chart views.
- Adding a component-test framework solely for this small integration.

## Technical approach

- Use Vite's ESM TypeScript configuration and `server.proxy`.
- Reserve `/api` as the frontend-facing API prefix and rewrite `/api/health` to backend `/health` during local development.
- Fetch `/api/health` from React so browser requests remain same-origin and require no CORS relaxation.
- Validate the response shape before displaying the backend version.
- Cancel the request during effect cleanup so React Strict Mode does not leave obsolete work behind.

## Acceptance criteria

1. The frontend requests backend health through its own origin.
2. Vite forwards the request to FastAPI without a browser CORS dependency.
3. A successful response displays that the backend is connected, including its version.
4. Loading and failure states are visible and accessible as status text.
5. Frontend lint and production build pass.
6. With FastAPI and Vite running, the proxied health URL returns HTTP 200 and the expected JSON.

## Edge cases and risks

- Backend unavailable: the UI must show an unavailable state without throwing or blanking the page.
- Malformed/non-JSON response: treat it as unavailable rather than trusting an unchecked payload.
- React Strict Mode can run effects twice in development; cleanup must abort the superseded request.
- Proxy rewrite must affect only the leading `/api` prefix.
- Production builds do not use the Vite development proxy; production hosting is outside T013 and must not be implied as solved.
- API response text must not be injected as HTML.
