# T021 — CSV 인코딩 자동 감지

## 문서 성격과 현재 상태

기존 작업의 사후 보완 문서다. 당시 Task Analysis·리뷰 기록을 새로 만든 것으로 취급하지 않는다.

- 기준: 2026-10-01 dev `019ee84`
- 백로그 상태: `done` / 에픽: `E2` / 예상: 20분
- 후행 작업: [T022](T022.md), [T057](T057.md)

## 쉽게 이해하기

한글 파일이 깨지지 않도록 파일을 읽을 수 있는 문자 인코딩을 차례로 시도한다.

## 의존 작업

- [T020](T020.md): `done` — 폴더 내 CSV 목록 수집

## 범위와 완료 기준

UTF-8 / UTF-8-BOM / CP949 순서로 시도하여 읽기

1. CP949 한글 CSV가 깨지지 않고 읽힘

이 문서는 범위 밖의 기능 구현, 백로그 상태 변경, 새 리뷰 판정을 수행하지 않는다.

## 관련 요구사항

[problem.md](../../problem.md)의 §3 입력 데이터, §4 축소 기준 컬럼을 참고한다. 제목과 절 구성은 작업 시작 때 다시 확인한다.

## 현재 코드 근거와 관련 파일

- [backend/app/core/ingest.py](../../backend/app/core/ingest.py) — 현재 존재하는 참고 파일.
- `detect_encoding`: 앞부분을 실제로 읽어 보며 깨지지 않는 인코딩을 고른다.
- `read_csv`: CSV를 읽어 (데이터프레임, 사용한 인코딩)을 돌려준다.

주의: ENCODINGS는 utf-8-sig, utf-8, cp949, euc-kr, latin-1 순이다. 백로그의 간단한 설명보다 현재 지원 범위가 넓다.

## 검증 근거와 다음 확인

- [backend/tests/test_ingest.py](../../backend/tests/test_ingest.py) — 기존 테스트 9개 함수. 해당 Task 기준을 모두 입증하는지는 재검토 필요.
- 확인 명령: backend에서 `python -m pytest -q tests/test_ingest.py`
- 이번 보완에서는 문서·코드 연결과 백로그 기준을 확인했다. 기능 테스트 재실행이나 성능 측정은 하지 않았다.
- 위 완료 기준별로 입력과 기대 출력을 대조하고 실제 실행 결과를 다음 리뷰에 남긴다.

## 경계 사례와 위험

빈 파일, 한글 인코딩, 없는 컬럼, 전체 결측, 상수 컬럼, 서로 다른 스키마를 확인한다.

## 줄 수 제한

core 파일 300/함수50, API 파일200/함수40, backend 테스트400/함수60, TSX250/함수80, TS200/함수50, scripts200/함수50 (공백 제외). 정확한 적용 규칙은 [hooks/config.json](../../hooks/config.json) 참고.

## 확인되지 않은 내용

- 당시 작업자, 정확한 변경 목록, 당시 실행 명령·검사 결과는 기존 기록이 없는 한 알 수 없다. 현재 구현이 당시 구현과 동일하다고 단정하지 않는다.
- 문서의 상태는 위 기준 시점 스냅샷이며 이후 상태 변경을 자동 반영하지 않는다.
