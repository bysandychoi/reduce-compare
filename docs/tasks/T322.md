## 목표

공정 Scheduling 관계 데이터를 `samples/web-demo`에서 바로 폴더 업로드할 수 있는 합성 CSV 세트로 제공한다. 기존 매출 데모는 그대로 두고, 사용자가 새 하위 폴더만 선택하면 Lot·설비·Resource·Spec 데이터 그룹을 각각 읽고 시각화 흐름에 사용할 수 있어야 한다.

## 확인한 현재 동작

- `samples/README.md`는 web-demo 폴더 선택 방법과 매출 데이터 파일 구성을 설명한다.
- `samples/web-demo`에는 월별 매출 CSV 2개와 고객 CSV 1개가 있다.
- `frontend/src/FolderPicker.tsx`는 폴더를 재귀 탐색하며 상대 경로를 유지한다.
- `problem.md` 및 `backend/app/core/schema.py` 기준, 입력 CSV는 컬럼 스키마가 같으면 병합 그룹으로, 다르면 별도 그룹으로 처리한다.
- 2D 투영은 `backend/app/core/projection.py`에서 원본 행이 최소 4개 필요하다. 샘플은 소규모 업로드 데모이므로 각 테이블에 충분한 행을 생성한다.
- T320의 기준 데이터는 Lot 1개, 설비 3개, 설비별 Resource 3~4개, 설비별 Spec 3개이며 공유 Resource ID를 포함한다.

## 범위

- 결정적 규칙으로 T320 관계를 바탕으로 여러 합성 Lot과 후보 설비 데이터를 생성한다. 기준 `LOT-24017`의 원본 값은 보존하고 변형 행은 분명한 합성 예시로 표시한다.
- 별도 폴더 `samples/web-demo/factory-scheduling/`에 4개의 관계형 CSV 생성:
  - `lots.csv`: Lot ID, product, operation, quantity, due/priority/recipe 등
  - `equipment_options.csv`: lot_id와 equipment_id를 연결한 적합성·처리 시간 데이터
  - `equipment_resources.csv`: lot/equipment/resource ID, 공유 여부, 관측값·단위
  - `resource_specs.csv`: lot/equipment/resource ID, spec 항목, 요구·실측값, 판정
- 모든 표에 join 가능한 ID와 명시적 단위를 넣고, 동일 Resource ID는 관련 설비 행에서 재사용한다.
- 기존 web-demo 파일을 덮어쓰지 않으며 `samples/README.md`에 새 데모 폴더 선택법, 표 스키마/키, 재생성 방법을 추가한다.
- 전역 `*.csv` 무시 규칙은 유지하되 이 합성 데모 폴더의 CSV만 저장소 관리 대상으로 예외 처리한다.
- 스크립트 실행 시 행 수, 키 참조, 공유 Resource 일관성을 검증하고 실패 시 명확한 오류를 낸다.

## 경계 조건과 위험

- 각 테이블은 서로 다른 스키마 그룹이어야 하며, 같은 종류의 ID/값 컬럼은 행 전체에서 타입이 안정적이어야 한다.
- 파일 인코딩은 기존 샘플과 같은 UTF-8 계열로 고정한다.
- 빈 파일, 중복 PK, 누락 FK, 잘못된 설비/Resource ID, 잘못된 Spec 판정은 생성기 검증에서 거부한다.
- CSV 출력 경로 기본값은 `samples/web-demo/factory-scheduling`; 다른 경로 사용 시 그 경로 아래만 생성/덮어쓴다.
- 단위와 요구 범위는 문자열·숫자 컬럼을 분리해 수치형 분석이 의미를 잃지 않게 한다.
