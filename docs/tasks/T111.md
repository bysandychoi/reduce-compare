# T111 — 지표 계산 서브샘플링 적용

## 작업 분석

- 백로그 기준: `todo`, E11, 예상 25분. 의존 T110(`done`).
- 요구사항: [problem.md §8](../../problem.md) — 50만 행 업로드부터 결과 화면까지 2분 이내. T111의 수락 조건은 50만 행에서 목표 시간 내 처리.
- 현재 코드: `backend/app/core/structure.py`에 trustworthiness 최대 3,000행, coverage 최대 20,000행 서브샘플이 이미 존재한다. T110 벤치마크는 50만 그룹 A 입력(추가 그룹 포함 총 625,000행)에서 탐색부터 투영까지 63.33초로 측정했다. 이 측정은 UI/업로드를 포함하지 않는다.
- 구현: 기존 상한을 작은/큰 입력 모두에서 검증하는 회귀 테스트를 추가했다. 측정값이 기준 안에 들어 핵심 지표 로직의 상한을 더 낮추지 않았다.
- 비목표: 다른 지표(분포·상관) 의미 변경, API/UI 변경, 전체 제품의 2분 목표 달성 주장.
- 완료 기준: trustworthiness 입력이 최대 3,000, coverage 입력이 최대 20,000으로 제한됨을 테스트로 보장하고, 50만 그룹 A 입력 벤치마크의 파이프라인 총 시간이 120초 이내임을 기록한다.

## 관련 구현 및 검증

- `backend/app/core/structure.py`: `TRUST_SUBSAMPLE`, `COVERAGE_SUBSAMPLE`, `_subsample`, 지표 함수.
- `backend/tests/test_metrics.py`: 고정 상한 및 작은 입력 경계 회귀 테스트를 추가할 위치.
- `scripts/benchmark.py --rows 500000`: 재현 가능한 합성 CSV 벤치마크(생성 시간 및 UI 제외).
- 검증: 해당 지표 테스트, Ruff, compileall, 50만 행 벤치마크.

## 경계·위험

- 작은 입력은 원본 전체를 써야 하며, 상한보다 큰 입력에서만 결정적 서브샘플을 사용한다.
- 표본 수 상한은 런타임을 낮추지만 원본 전체의 세부 구조를 완전히 반영한다는 뜻은 아니다.
- 벤치마크 시간은 시스템 부하 영향을 받으며 제품 전체 목표의 증거와 혼동하면 안 된다.

## 검증 결과

- `backend/.venv/Scripts/python.exe -X utf8 -m pytest tests/test_metrics.py -q` (backend 기준): 15 passed.
- Ruff 및 `compileall` 대상 파일 통과.
- `scripts/benchmark.py --rows 500000`: 요청 500,000행, 실제 합계 625,000행, 총 파이프라인 60.41초(탐색·스키마 0.15, 병합·전처리 1.88, 크기 탐색 24.38, 방식 비교 33.98, 투영 0.03초). 120초 기준 이내.
- 벤치마크는 합성 CSV 생성과 브라우저 업로드/렌더링을 제외한다.
