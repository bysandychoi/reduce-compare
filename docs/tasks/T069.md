## 쉽게 말하면
`--limit` 플래그가 다중 컬럼을 받을 때 순서를 명확하게 하고, 각 컬럼의 역할을 구분한다. 단위 컬럼(예: lot_id) 제한은 최종 결과의 행 개수를 보장하고, 그룹 속성(예: eqp_id, mask_id) 제한은 그룹을 선별하거나 행을 거른다. 이를 통해 축소 결과가 예측 가능하고 재현 가능해진다.

## 주의할 점
- **limit의 두 역할 구분**: 단위 컬럼(unit_col) limit(예: lot_id=100)은 최종 결과의 행 개수를 보장하고 --ratio 단위 축소를 생략한다. 비단위 컬럼(예: eqp_id=6,mask_id=6)은 행이나 그룹을 미리 제거한다.
- **순서 중요**: 현재 코드가 적힌 순서대로 거르기 때문에, 단위 컬럼 limit을 먼저 적용했을 때와 뒤에 적용했을 때 결과가 다를 수 있다. 명시적으로 정의해야 한다.
- **재현 데이터**: /tmp/claude-0/-home-user-reduce-compare/e9a51765-598c-5d4a-a22d-828cefc40938/scratchpad/units/data/lots.csv (600 lot 합성 데이터) — 현재 37개로 줄고 --ratio 0.2 후 36개
- **출력 부분 분리 시 주의**: apply_limits, main이 각각 50줄 이하가 되도록 기능을 나누고, 새 모듈 format_output.py를 만든다. 스크립트는 이미 200줄 한계를 초과했다.
- **유사도 계산 시점**: eqp·mask 제한 후(행 제거 후) 데이터를 기준으로 계산해야 한다. 제한 전 데이터 기준이면 안 된다.

## 작업 기록
- `valuelimit.split_limits(limits, unit_cols)`: limit을 (행 필터, 단위 컬럼)으로 나눔.
- `grouped.units_by_values(df, unit_cols, strata_cols, keep)`: 고른 단위 컬럼 값의 행을 통째로 남기는 GroupedReduction (층별 가중치는 `_row_weights` 그대로).
- `run_reduce_units.py`: `apply_limits`가 행 필터 → 단위 컬럼 선택 순서로 적용, `reduce_group`이 keep이 있으면 비율 축소 생략. `main`을 `parse_args`/`run_group`/`main`으로 나눔. 출력 함수는 `scripts/units_report.py`로 분리(167/200줄, 65/200줄).
- 확인: 600 lot 합성 데이터, `--limit lot_id=100,eqp_id=6,mask_id=6 --ratio 0.2` → 결과 lot 100, eqp 6, mask 6 (이전: lot 36). 단위 컬럼 limit 없이(`--limit eqp_id=20,mask_id=30`) 이전 버전과 reduced CSV·report JSON 동일.
- 테스트: `backend/tests/test_unit_limits.py` 5건 (split, units_by_values 가중치·오류, CLI 최종 lot 수·가용 lot 부족). pytest 204 passed.
