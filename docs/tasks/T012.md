# T012 Task Analysis — 프론트엔드 React(Vite) 초기화

## Task and dependency status

- Task: T012, 프론트엔드 React(Vite) 초기화
- Status: `in_progress`
- Estimate: 20 minutes
- Dependency: T010 (`done`), 저장소 구조 생성
- Downstream tasks: T013, T070
- Active branch: `dev`

## Scope

- Confirm the frontend is a Vite + React + TypeScript ESM project.
- Confirm React, ReactDOM, and Plotly are declared dependencies.
- Confirm the application mounts into the HTML root and renders an initial page.
- Confirm ESLint, TypeScript compilation, and the Vite production build succeed.
- Start the Vite development server and verify the root page is served over HTTP.
- Make only the smallest frontend changes needed to satisfy these checks.

The repository already contains an implementation and installed dependencies in `frontend/`; this task validates that implementation and repairs only T012 initialization gaps.

## Non-goals

- Backend API integration, proxy configuration, or CORS handling.
- Upload, configuration, results, chart, or navigation UI.
- Rendering a Plotly chart; T012 only installs the graph dependency for later tasks.
- Automated browser interaction tests or a component test framework.
- Dependency major-version migrations unrelated to initialization.

## Acceptance criteria

1. `frontend/package.json` defines a Vite + React + TypeScript project using ESM.
2. React, ReactDOM, and Plotly are declared and resolvable after `npm install`.
3. `npm run lint` succeeds.
4. `npm run build` succeeds and emits the production bundle.
5. `npm run dev` starts Vite and its root URL returns HTTP 200 with the application HTML.
6. The initial React page mounts without requiring backend data or user input.

## Relevant requirements

- `problem.md` §2: the product is a local web application accessed in a browser.
- `problem.md` §5–§6: later results use interactive comparison and graph views; Plotly is an accepted graph-library choice.
- `problem.md` §8: browser interaction must remain smooth, while heavy computation belongs in the backend. T012 establishes only the frontend shell.

## Existing and expected files

- `frontend/package.json` and `frontend/package-lock.json`: scripts and dependency graph.
- `frontend/vite.config.ts`: ESM Vite configuration with the official React plugin.
- `frontend/tsconfig.json`: strict TypeScript settings.
- `frontend/eslint.config.js`: source lint configuration.
- `frontend/index.html`: root HTML document.
- `frontend/src/main.tsx`: React mounting entry point.
- `frontend/src/App.tsx`: initial visible page.
- `frontend/src/styles.css`: minimal page styling.

No additional application file is expected unless verification exposes a gap.

## Test plan

- Run `npm install` to verify the lockfile and dependencies can be installed.
- Run `npm run lint`.
- Run `npm run build` and confirm the generated entry HTML exists.
- Start `npm run dev` on an available localhost port and request `/` over HTTP.
- Inspect the served HTML for the Vite React entry module and confirm status 200.

## Edge cases and risks

- A stale `node_modules` directory can hide lockfile or declared-dependency problems; `npm install` must still succeed.
- The configured port may already be occupied; verification may use an explicit alternate port without changing project configuration.
- The HTML root ID and the React lookup must match exactly or runtime mounting fails.
- Build success alone does not prove the development server starts, so both paths must be checked.
- Plotly is large; T012 confirms installation only and does not import it into the initial bundle unnecessarily.
- The application shell must not require the unavailable backend to render.

The existing T012 source files are well below these limits.

- Whether the current npm cache is sufficient for a clean reinstall without registry access is unknown until installation runs.
- Browser-level visual appearance is not part of T012's explicit acceptance criterion; HTTP serving and React mounting structure are the proportional checks for the initial shell.
