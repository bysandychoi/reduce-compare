# T142 반영 리포트 API

## 상태와 의존성

- 백로그: `todo` (Task Analysis 시점), E14
- 선행: T140 군집 반영 통계, T141 관계 변화 원인 분류, T064 결과 조회 API 모두 `done`
- 후속: T144~T146

## 목표

완료된 작업의 저장 결과를 사용해 군집 반영 표, 관계 변화·원인 후보, 원본/축소 규모 및 투영 점을 한 번에 반환하는 `GET /jobs/{id}/report`를 제공한다.

## 범위

- 선택 결과에 실제 `cluster_report`를 JSON 안전 형태로 저장
- 비군집 방식에도 “군집 분석 미적용”을 구분할 수 있는 유효한 단일 요약 보고서 구성
- `group`과 `threshold` 쿼리로 결과 그룹 및 관계 임계값 선택
- 기존 상관 결과를 `explain_relationship_changes`에 연결
- 기존 projection의 원본/축소 점과 행 규모 반환
- Pydantic 응답 모델 및 API 회귀 테스트

## 비범위

- 반영 리포트 React UI(T144~T146)
- 재계산을 위한 원본 CSV 재독해
- 관계 원인 알고리즘 또는 투영 알고리즘 변경

## 완료 기준

1. 완료 job의 `GET /jobs/{id}/report?group=...`가 규모, 점, 군집 보고서, 관계 변화 결과를 반환한다.
2. 실행 전/진행/실패/손상 결과는 기존 결과 API와 일관된 HTTP 오류를 반환한다.
3. 없는 그룹과 잘못된 임계값을 거부한다.
4. undefined 상관 쌍과 “인과 증명이 아님” 표기가 보존된다.
5. backend lint와 관련 테스트가 통과한다.

## 관련 파일

- `backend/app/core/pipeline.py` — cluster report를 선택 결과 detail에 보존
- `backend/app/api/reports.py` — 신규 라우터와 응답 모델
- `backend/app/main.py` — 라우터 등록
- `backend/tests/test_reports.py` — 성공/경계/오류 회귀 테스트

## 경계 조건과 위험

- 과거 result.json이나 비군집 방식에는 cluster report가 없을 수 있다.
- API는 저장된 projection을 재사용해 축소 파이프라인을 재실행하지 않는다.
- 상관 detail이 없거나 손상되면 422로 명확히 응답한다.
- projection 점 차원과 규모 메타데이터의 불일치는 손상 결과로 거부한다.
