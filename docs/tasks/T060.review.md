## Acceptance review

1. **Job creation:** PASS. Valid multipart uploads return HTTP 201 with a unique hexadecimal `job_id`.
2. **Persistence:** PASS. Accepted bytes are streamed beneath `tmp/jobs/<job_id>/uploads`.
3. **Multiple/relative files:** PASS. Safe nested paths are preserved and verified on disk.
4. **Empty or unsupported input:** PASS. Unsupported-only requests return 400 before job creation.
5. **Path safety:** PASS. Traversal, absolute/drive paths, empty segments, and duplicate destinations are rejected.
6. **Quality gates:** PASS. Ruff, all 58 backend tests, frontend lint/build, and whitespace checks passed.

## Adversarial checks

- Large files are read in bounded 1MB chunks rather than buffered wholly in application memory.
- UUID4 job directories isolate concurrent requests.
- Exclusive file creation prevents unnoticed overwrite even if filesystem state changes after validation.
- Partial write failures remove the complete job directory before propagating the error.
- User filenames are never interpreted as absolute filesystem targets.
- Backslash and slash inputs receive the same validation on Windows.
- Unsupported parts are ignored when at least one supported table file is present, matching folder collection behavior.
- Empty accepted files are retained for the ingestion layer to diagnose, preserving task separation.
- The response exposes only the generated identifier and normalized relative names, not local absolute paths.
