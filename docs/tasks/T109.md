# T109 Task Analysis — Windows CP949 CLI 출력 호환성 수정

## Task and dependency status

- Task: T109, Windows CP949 CLI 출력 호환성 수정
- Status: `todo` at analysis time; move to `in_progress` before implementation.
- Estimate: 15 minutes
- Dependencies: none
- Downstream tasks: none
- Active branch: `dev`

## Scope

- Prevent `scripts/run_reduce_units.py` from raising `UnicodeEncodeError` when a group is skipped in a Windows CP949 console.
- Keep the Korean skip reason readable while replacing the unsupported em dash separator with a CP949-safe character.
- Run the unit-limit CLI subprocess tests with an explicit CP949 stdout encoding so the regression is deterministic even when pytest itself runs in UTF-8 mode.
- Cover both the normal/inspect output path and the skipped-group path through the existing CLI tests.

## Non-goals

- Translating Korean CLI output, changing reduction behavior, or altering generated CSV/JSON artifacts.
- A repository-wide typography rewrite of all scripts and documentation.
- Changing Windows code pages, terminal settings, Python installation settings, or global standard-stream error handling.
- Fixing plot-only en dash labels that are not written to the console.

## Technical approach

- Replace the skip message separator `—` (U+2014, not encodable in CP949) with ASCII `-` in `run_reduce_units.py`.
- Preserve the existing message wording and return behavior so missing-column groups are skipped while valid groups continue.
- In `test_unit_limits.py`, launch the CLI with `PYTHONIOENCODING=cp949` and decode captured output as CP949.
- Update the skip assertion to the safe separator; existing inspect/output assertions then exercise the same forced console encoding.

## Acceptance criteria

1. `run_reduce_units.py --inspect` completes under an explicitly CP949-encoded stdout stream.
2. A folder containing one valid group and one group missing a requested limit column prints the Korean skip reason and exits successfully under CP949.
3. The valid group still produces its reduced CSV; reduction semantics and report values are unchanged.
4. Focused tests, the full backend suite in UTF-8 and default Windows conditions, Ruff/compile checks, frontend regression gates, and diff checks pass.

## Relevant requirements

- `problem.md` §2: the application is intended to run on a local PC, including Windows environments.
- `problem.md` §7: users must be able to inspect input and proceed through reduction without terminal-output crashes.
- T109 backlog acceptance: inspect/skip messages print on a Windows CP949 console without `UnicodeEncodeError`.

## Existing and expected files

- `scripts/run_reduce_units.py`: change the unsupported console separator only.
- `backend/tests/test_unit_limits.py`: force CP949 in CLI subprocesses and update the expected skip text.
- No backend application or frontend production file should change.

## Test plan

- Run `test_cli_group_without_limit_column_is_skipped` under the forced CP949 subprocess environment.
- Run all `test_unit_limits.py` tests to cover regular output and saved artifacts.
- Run the full backend suite without `PYTHONUTF8`; the previously observed CP949 failure must disappear.
- Run the full backend suite with UTF-8 to ensure cross-encoding compatibility.
- Run Ruff, compileall, frontend lint/build, and `git diff --check`.

## Edge cases and risks

- The child process encoding must be explicit on both output and parent decoding, otherwise UTF-8 CI may hide the Windows failure or misdecode valid CP949 bytes.
- Environment variables should be copied and augmented rather than replacing the child's whole environment.
- Korean text, arrows, middle dots, multiplication signs, and ellipsis currently used by this CLI are CP949 encodable; only the em dash in the console path is in scope.
- The generated artifact encodings remain UTF-8/UTF-8-SIG and must not be changed to CP949.
