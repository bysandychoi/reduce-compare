기존 작업의 사후 보완 문서다. 당시 Task Analysis·리뷰 기록을 새로 만든 것으로 취급하지 않는다.

## 쉽게 이해하기

선택한 기준 컬럼에 빈 값이 있는 행을 제외하고 제외한 개수를 기록한다.

## 의존 작업

- [T001](T001.md): `done` — 결측치·이상치 처리 방식 결정
- [T024](T024.md): `done` — 그룹별 데이터 병합

## 범위와 완료 기준

결측이 있는 행을 제외하고, 제외 건수를 결과에 기록

1. 결측 포함 데이터가 규칙대로 처리됨

이 문서는 범위 밖의 기능 구현, 백로그 상태 변경, 새 리뷰 판정을 수행하지 않는다.

## 관련 요구사항

[problem.md](../../problem.md)의 §3 입력 데이터, §4 축소 기준 컬럼을 참고한다. 제목과 절 구성은 작업 시작 때 다시 확인한다.

## 현재 코드 근거와 관련 파일

- [backend/app/core/prepare.py](../../backend/app/core/prepare.py) — 현재 존재하는 참고 파일.
- `drop_missing_rows`: 기준 컬럼에 결측이 있는 행을 제외한다 (T025). (남은 데이터, 제외 건수).
- `prepare_group`: 병합된 데이터에 전처리를 한 번에 적용한다 (T025~T027).

## 검증 근거와 다음 확인

- [backend/tests/test_prepare.py](../../backend/tests/test_prepare.py) — 기존 테스트 9개 함수. 해당 Task 기준을 모두 입증하는지는 재검토 필요.
- 확인 명령: backend에서 `python -m pytest -q tests/test_prepare.py`
- 이번 보완에서는 문서·코드 연결과 백로그 기준을 확인했다. 기능 테스트 재실행이나 성능 측정은 하지 않았다.
- 위 완료 기준별로 입력과 기대 출력을 대조하고 실제 실행 결과를 다음 리뷰에 남긴다.

## 경계 사례와 위험

빈 파일, 한글 인코딩, 없는 컬럼, 전체 결측, 상수 컬럼, 서로 다른 스키마를 확인한다.

## 줄 수 제한

core 파일 300/함수50, API 파일200/함수40, backend 테스트400/함수60, TSX250/함수80, TS200/함수50, scripts200/함수50 (공백 제외). 정확한 적용 규칙은 [hooks/config.json](../../hooks/config.json) 참고.

## 확인되지 않은 내용

- 당시 작업자, 정확한 변경 목록, 당시 실행 명령·검사 결과는 기존 기록이 없는 한 알 수 없다. 현재 구현이 당시 구현과 동일하다고 단정하지 않는다.
- 문서의 상태는 위 기준 시점 스냅샷이며 이후 상태 변경을 자동 반영하지 않는다.
