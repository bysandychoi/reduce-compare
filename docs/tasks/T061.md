# T061 Task Analysis — 폴더 구성 판별 결과 API

- Task: T061, 폴더 구성 판별 결과 API
- Status: `todo` at analysis time; must move to `in_progress` before application changes.
- Estimate: 25 minutes
- Dependencies: T023 (`done`), T060 (`done`)
- Downstream tasks: T062, T067, T074
- Active branch: `dev`

## Scope

- Add `GET /jobs/{job_id}/groups` to inspect uploaded table files, extract schemas, and return deterministic schema groups.
- Expose each group's files, columns, and default/current merge decision.
- Add `PUT /jobs/{job_id}/groups` to update merge decisions for every known group.
- Persist user decisions inside the temporary job directory so later API calls can consume them.
- Return clear errors for missing jobs, jobs without readable tabular files, malformed input, and unknown/duplicate group IDs.
- Add focused API tests and full regression verification.

## Non-goals

- Changing group membership or column schemas through the PUT endpoint.
- Reading full datasets, merging frames, reduction, background jobs, or progress tracking.
- Database persistence or cleanup scheduling.
- Frontend group-selection UI.

## Technical approach

- Reuse `collect_csv_files`, `extract_schema`, and `group_by_schema` against `tmp/jobs/<id>/uploads`.
- Assign deterministic IDs by the existing stable group order: `group-1`, `group-2`, and so on.
- Serialize only API-facing values; never expose absolute server paths.
- Store merge overrides as a small JSON file under the job directory and apply them on subsequent GET requests.
- Require PUT to include each current group exactly once, preventing stale or partial configurations from silently surviving.

## Acceptance criteria

1. GET returns same-schema files together and different schemas separately.
2. Response includes deterministic group IDs, relative file names, column metadata, and merge decisions.
3. PUT changes merge decisions and a following GET returns the saved values.
4. Missing jobs and jobs with no readable table files return 404/422-style client errors rather than server failures.
5. Unknown, duplicate, missing, or malformed group updates are rejected without replacing valid saved state.
6. API tests, full backend tests, Ruff, frontend lint/build, and diff checks pass.

## Relevant requirements

- `problem.md` §3: identical column structures are merged; differing structures are handled separately.
- `problem.md` §3: the detected choice is displayed and the user can switch merge/individual handling.
- `problem.md` §4: column metadata and default selections feed later reduction configuration.

## Existing and expected files

- `backend/tests/test_job_groups.py`: focused grouping and update tests.
- `backend/app/core/ingest.py`: collect uploaded table files.
- `backend/app/core/schema.py`: extract and group schemas.

## Test plan

- Create uploaded jobs through `POST /jobs`, then query groups.
- Verify identical and differing schemas, deterministic order, relative names, and column metadata.
- Update merge flags and verify persistence on subsequent GET.
- Test missing job, unsupported/non-tabular uploads, unknown, duplicate, and incomplete group updates.
- Verify a rejected PUT does not overwrite prior state.
- Run Ruff, all backend tests, frontend lint/build, and diff checks.

## Edge cases and risks

- Uploaded `.txt` can pass extension filtering but later prove non-tabular; collection must skip it cleanly.
- Empty/malformed CSV may fail schema extraction; return a client-facing validation error without corrupting saved decisions.
- Group IDs based on order remain stable only while uploaded files are immutable, which T060 guarantees after creation.
- JSON state writes should be replaced atomically to avoid a partially written decision file.
- Job IDs are untrusted path segments and must be validated before filesystem lookup.
- API responses must not leak absolute local paths.

## Line limits

From `hooks/config.json`:

- API routers: at most 200 non-blank lines per file and 40 per function.
- Backend tests: at most 400 non-blank lines per file and 60 per function.

The existing jobs router may need helpers or a second API module if extending it would approach the router limit.

## Unknowns

- Whether later UI should support per-file overrides inside a same-schema group is not specified; T061 implements only the backlog's group-level merge/individual decision.
