# T113 — 파이프라인 진행률 콜백 연결

## 작업 분석

- 백로그 기준: `todo`, E11, 예상 20분. 의존 T054(`done`), T063(`done`).
- 요구사항: [problem.md §8](../../problem.md) — 무거운 계산의 진행 상태를 표시한다. 완료 기준은 UI 진행률이 실제 파이프라인 단계와 일치하는 것이다.
- 구현: `backend/app/core/pipeline.py`에서 파일·스키마 확인과 그룹별 병합/전처리·크기 탐색·방식 비교·투영 이벤트를 (단계명, 전체 0~1 fraction) 콜백으로 전달한다. 그룹별 가중 구간은 순서대로 배분하고 건너뛴 그룹도 구간을 소모한다. 검색 콜백은 병렬 후보 배치가 끝난 호출자 스레드에서만 보고한다.
- `backend/app/api/runs.py`의 `PipelineProgressWriter`가 fraction을 20~85%로 매핑해 단조 증가하도록 원자적 `run.json`에 기록한다. 실행 준비 10%, 결과 저장 90%, 완료 100% 구간은 보존한다. 저장 실패도 실제 `결과 저장` 단계로 반환한다. `frontend/src/RunPanel.tsx`는 API `progress`/`stage`를 이미 표시하므로 프론트 코드 변경은 없다.
- 범위: 레이아웃이나 시각 스타일을 바꾸지 않고 실제 단계 상태만 연결한다.
- 완료 기준: 콜백 이벤트별 상태 저장 검증; 전체 진행도 단조 증가, 실패 시 마지막 실제 단계명과 진행도 유지; UI가 기존 API 상태를 표시하는 것 확인.
- 비목표: 진행 UI 레이아웃/디자인 변경, 실시간 전송 기술 추가, 알고리즘·결과 형식 변경, 세부 연산 내부(각 KMeans 반복 등) 진행률.

## 구현 대상 및 검증 계획

- `backend/app/core/pipeline.py`: 선택적 콜백 인자, 파일/스키마와 그룹별 주요 단계 이벤트, 그룹 수를 고려한 전역 진행 구간.
- `backend/app/api/runs.py`: 콜백을 상태 파일 writer에 연결하고 단조 진행률 및 오류 stage 보존.
- `backend/tests/test_pipeline.py`, `backend/tests/test_job_status.py` 또는 `test_job_runs.py`: 단계 순서/진행값, 여러 그룹·건너뛴 그룹, 상태 API의 기록·실패 동작.
- 검증: 관련 pytest, Ruff, compileall, `frontend`에 변경이 있을 때만 ESLint/build.

## 경계·위험

- 그룹별 진행은 데이터 그룹 수에 비례해 배분하며 건너뛴 그룹도 진행 구간을 소모해야 100% 직전까지 정체되지 않는다.
- 병렬 크기 후보 완료 순서가 비결정적이어도 콜백 값은 감소하지 않아야 한다. 콜백은 검색 호출자 스레드에서 내보내거나 단조성을 보장한다.
- callback 미지정 시 기존 core API 호출 동작을 유지한다.
- 콜백 저장 오류는 실행 실패로 기록될 수 있으므로 실패 stage 및 JSON 원자 저장 동작을 검증한다.

## 시각 산출물

기존 RunPanel의 진행률 UI를 그대로 사용하며 배치/레이아웃 변경은 하지 않는다. 본 작업은 상태 로직 연결이므로 별도 이미지 샘플은 필요하지 않다.

## 검증 결과

- core callback 테스트: 이벤트 단계 순서와 단조 fraction, 잘못된 그룹 건너뜀 후 완료 구간 확인.
- core 진행 콜백이 `ValueError`를 내도 그룹 데이터 오류로 삼켜 건너뛰지 않는지 확인.
- API 테스트: running 중 콜백이 46% 및 `그룹 A · 크기 탐색 중`으로 저장되는지, 이후 실패에 같은 단계가 반영되는지 확인. 결과 저장 실패는 90%/`결과 저장`으로 보고.
- 전체 백엔드 회귀: UTF-8 하위 프로세스 환경에서 344 passed. Ruff 전체 백엔드 통과, compileall 통과.
- FastAPI TestClient에서 기존 `httpx` 지원 관련 Starlette deprecation warning 1건이 남아 있으나 테스트 실패는 없다.
