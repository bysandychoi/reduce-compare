# T008 — 백로그 대시보드 UX 개선

## 태스크/의존 상태
- 태스크: T008, 에픽 E0(인프라), 상태 todo → in_progress
- 의존: 없음
- 리뷰 요구: E0는 `review.exempt_epics`에 포함되어 done 전환 시 어드버서리얼 리뷰 필수 아님

## 배경 / 사용자 요청 (원문 그대로 정리)
1. Task를 클릭하면 자세한 설명이 나오는 기능이 필요할 것 같다.
2. 상태 글자가 흰색이라 잘 안 보인다.
3. "E"가 에픽을 의미하는지 확인 — 에픽별로 보이게 표시.
4. 간트 차트를 위쪽으로 재배치.

## 조사 결과
- 대상 파일: `scripts/backlog_dashboard.html` (단일 파일, 읽기 전용 백로그 뷰어, 순수 HTML/CSS/JS)
- 1) 상세 패널(`#detail`)은 이미 구현되어 있음(`selectTask` → `renderDetail`). 다만 테이블 아래 멀리 위치해 클릭해도 화면 밖이라 안 보일 수 있음 → 클릭 시 상세 영역으로 스크롤 필요.
- 2) `.status-pill`/`.chip`의 배경(`#fff4d6`, `#e2f5e6`, `#fde3e3` 등)은 밝은 색인데 다크 모드 전역 규칙(`.chip, .status-pill { background: #2b2d30; ... }`, line 89)이 상태별 배경을 덮어써 다크모드에서 텍스트 색 상속(`body`의 `#e7e7e7`)과 맞물려 저대비가 아니라, 실제로는 라이트 모드에서도 텍스트 색이 지정 안 돼 있어 밝은 배경 위에 밝은 상속색(다크모드 대응 시)일 때 대비가 낮음. → 상태별 텍스트 색을 명시적으로 지정.
- 3) `epic` 컬럼은 이미 "에픽" 헤더로 표시 중(테이블 두 번째 컬럼, line 137, 552). 사용자가 원하는 것은 테이블을 에픽별로 그룹핑해서 보여주는 것 → `renderTable`을 에픽별 그룹 헤더 행 삽입 방식으로 변경.
- 4) `#ganttSection`(간트, id 143)이 `#tableSection`(테이블, id 134)보다 DOM 순서상 아래에 있음 → 두 섹션의 DOM 순서를 맞바꿔 간트가 필터/테이블보다 위에 오도록 배치. `computeSchedule()`은 `renderTable()` 이후에 실행되므로 순서 종속성 없음(HTML 배치만 변경, JS 로직 순서는 유지).

## 범위 (Scope)
- `scripts/backlog_dashboard.html` 내에서만 작업 (CSS + JS + HTML 마크업 순서)
- 태스크 행 클릭 시 `#detail`로 스크롤
- 상태 pill/칩 텍스트 색상 명시 (라이트/다크 모두 대비 확보)
- 테이블을 에픽 단위로 그룹 헤더와 함께 렌더링
- 간트 차트 섹션(`#ganttSection`)을 필터/테이블 섹션보다 위로 이동

## 비범위 (Non-goals)

- 간트 차트 내부 로직(스케줄 계산) 변경 없음 — 위치만 이동

## 추가 수정 (1차 done 이후 사용자 피드백)
- 사용자가 "상세 보기가 안 된다"고 재현: 1차 구현에서 스크롤만 추가했지 실제 원인은 따로 있었음.
  `renderDetail()`이 `box.style.display = ""`로 인라인 스타일을 지워서 기본값으로 되돌렸는데,
  `#detail`은 스타일시트에 `display: none;` 규칙이 박혀 있어(line 38) "" 로 되돌리면 그 규칙이
  그대로 적용되어 계속 숨김 상태였음(1차 구현 이전부터 있던 기존 버그, 스크롤 추가만으론 못 고침).
  → `renderDetail`에서 `t`가 있으면 `display = "block"`, 없으면 `display = "none"`으로 명시 지정하도록 수정.
- 간트 차트도 테이블처럼 에픽별 그룹 헤더(`.gantt-group-row`)로 묶어서 표시하도록 변경(`groupByEpic` 재사용,
  그룹 내부는 기존처럼 시작 시각 기준 정렬 유지).

### 추가 수용 기준
5. 태스크 행 클릭 시 상세 패널이 실제로 화면에 표시됨(단순히 스크롤되는 것이 아니라 `display`가 보이는 값이어야 함)
6. 간트 차트가 테이블과 동일하게 에픽별 그룹 헤더와 함께 표시됨

## 추가 수정 2 — 상세 패널 레이아웃 (옆으로 배치)
- 사용자 피드백: 상세 보기가 테이블/간트 "아래"에 나오는 게 불편함 → 옆(사이드 패널)으로 배치 요청.
- `#ganttSection`/`#filterSection`/`#tableSection`을 `.main-col`로, `#detail`을 `.side-col`로 묶고 `.main-layout`
  (flex row)으로 감쌈. `.side-col`은 `position: sticky`로 스크롤 시에도 계속 보이도록 함(폭 380px).
  960px 이하에서는 `.main-layout { flex-direction: column; }`으로 기존처럼 세로 스택.
- `#detail`은 이제 태스크 미선택 상태에서도 항상 표시되며(placeholder 안내 문구), 선택 시 내용으로 교체됨.
- 데스크톱(사이드 패널 상시 노출)에서는 클릭 시 스크롤 이동이 불필요/방해가 되므로 제거하고,
  좁은 화면(≤960px, 세로 스택)에서만 `#detail`로 스크롤하도록 `selectTask`를 `matchMedia`로 분기.

### 추가 수용 기준
7. 상세 패널이 테이블/간트 차트 옆(오른쪽)에 사이드 패널로 표시됨 (넓은 화면 기준)
8. 좁은 화면(모바일 폭)에서는 기존처럼 세로로 쌓여 표시됨
9. 태스크 미선택 시에도 사이드 패널에 안내 문구가 표시됨(빈 공백이 아님)

## 추가 수정 3 — 연결된 문서(작업 안내서/리뷰) 가독성
- 사용자 피드백: "연결된 문서 → 작업 안내서 보기"를 누르면 마크다운 원문이 `<pre>`에 그대로 텍스트로 찍혀서
  `#`, `-`, `**` 같은 기호가 그대로 보여 읽기 어려움.
- 외부 라이브러리 없이(오프라인 단일 파일 도구 특성 유지) 최소 마크다운 렌더러를 추가:
  `escapeHtml`/`inlineMd`/`renderMarkdown` 함수로 제목(#~######), 굵게(**), 인라인 코드(`` ` ``),
  펜스 코드블록(```), 순서/비순서 목록, 구분선(---)을 HTML로 변환. 그 외 텍스트는 문단(`<p>`)으로 처리.
  XSS 방지를 위해 렌더 전에 항상 `escapeHtml`로 이스케이프 후 허용된 태그만 삽입.
- `docLinkNode()`의 `<pre>` 텍스트 덤프를 `renderMarkdown()` 결과로 교체(`.md-doc-wrap` 컨테이너,
  라이트/다크 모드 스타일 추가). 작업 안내서(`.md`)와 리뷰(`.review.md`) 둘 다 동일하게 적용.
- 검증: Node에서 `escapeHtml`/`inlineMd`/`renderMarkdown` 함수만 추출해 실제 `docs/tasks/T008.md`를
  렌더링한 DOM 트리를 출력해 제목/목록/인라인 코드가 의도대로 태그로 변환되는지 확인(수동, 자동화 테스트 없음).
  느슨한 리스트 연속줄(빈 줄 없이 들여쓰기만 다른 줄)은 CommonMark의 "lazy continuation"을 구현하지 않아
  별도 문단으로 끊길 수 있음 — 완전한 CommonMark 호환은 범위 밖으로 명시.

### 추가 수용 기준
10. "작업 안내서 보기"/"리뷰 보기" 클릭 시 마크다운이 제목/목록/굵게/코드 서식으로 렌더링됨(기호가 그대로 노출되지 않음)
11. 라이트/다크 모드 모두에서 렌더링된 문서가 읽기 편한 배경/글자색을 가짐

## 추가 수정 4 — 상세 패널 너비 확대 + 드래그 리사이즈
- 사용자 피드백: 상세 패널이 좁고 작게 느껴짐 → 기본 폭을 넓히고, 마우스로 너비를 조절할 수 있게 해달라는 요청.
- 기본 사이드 패널 폭을 380px → 520px로 확대, `.side-col section` 기본 글자 크기를 14px로 소폭 키움
  (세부 필드처럼 이미 명시적 13px가 지정된 곳은 특이도가 더 높아 그대로 유지됨).
- `.main-col`과 `.side-col` 사이에 `#dragHandle`(8px 폭의 드래그 핸들)을 추가하고 mousedown/mousemove/mouseup으로
  `.side-col`의 `flexBasis`를 실시간으로 갱신. 최소 320px, 최대 900px로 제한.
  드래그가 끝나면 `localStorage`(`backlogDashboardSideWidth`)에 저장해 다음 방문 시에도 유지.
  `localStorage` 접근이 막힌 환경(일부 `file://` 정책 등)에서도 조용히 무시하고 기본값으로 동작하도록 try/catch로 감쌈.
- 드래그 핸들은 데이터 로드 여부에 따라 사이드 패널과 함께 표시/숨김 처리되고, 960px 이하(세로 스택) 레이아웃에서는
  가로 리사이즈가 의미 없으므로 숨김.

### 추가 수용 기준
12. 상세 패널의 기본 폭이 이전보다 뚜렷하게 넓어짐(380px → 520px)
13. 메인 영역과 상세 패널 사이의 핸들을 마우스로 드래그하면 상세 패널 폭이 320~900px 범위에서 실시간으로 바뀜
14. 드래그 후 새로고침해도 마지막으로 조절한 폭이 유지됨(localStorage 사용 가능 환경 한정)
15. 좁은 화면(≤960px)에서는 드래그 핸들이 보이지 않고 기존처럼 세로 스택 레이아웃 유지
