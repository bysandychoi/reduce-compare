## 언제 쓰나요

`run_reduce.py`는 행을 하나씩 따로 뽑습니다. 그런데 lot-공정 이력처럼 **여러 행이 한 묶음**인 데이터에서
행을 따로 뽑으면 lot 하나의 이력이 중간중간 잘려 나갑니다.

`run_reduce_units.py`는 묶음(단위)을 통째로 남기거나 통째로 뺍니다. 그래서 남은 lot의 이력은 끊기지 않습니다.

| 이런 데이터라면 | 이 스크립트 |
|---|---|
| 행 하나하나가 독립적 (설문 응답, 거래 내역 등) | `run_reduce.py` |
| 한 묶음이 여러 행 (lot-공정 이력, 주문-상품 등) | `run_reduce_units.py` |

## 먼저 알아둘 두 가지: 단위와 층

### 단위 (`--unit`) — "통째로 남기거나 뺄 묶음"

이 컬럼 값이 모두 같은 행들이 한 단위입니다.

```
--unit lot_id,step_id,proc_id,proc_ver
```

`L0001`이 `STP003` 공정(`P3`, `v1`)에서 남긴 행이 3개라면, 그 3행이 한 단위입니다.
축소할 때 이 3행은 같이 남거나 같이 빠집니다.

### 층 (`--strata`) — "원본과 같은 비율로 맞출 기준"

이 컬럼 조합(층)마다 원본에 있던 단위 비율을 유지합니다.

```
--strata step_id,proc_id,proc_ver,lot_floor
```

원본에서 `STP003 × P3 × v1 × F1` 조합의 단위가 전체의 2%였다면, 축소본에서도 2%가 되도록 층마다 같은 비율로 단위를 뽑습니다.
드문 조합도 최소 1개(`--min-units`)는 남깁니다.

**층 컬럼 값은 한 단위 안에서 모두 같아야 합니다.** 단위 하나가 어느 층에 속하는지 정해져야 하기 때문입니다.
그래서 보통은 층 컬럼을 단위 컬럼에 포함시키거나(`step_id`, `proc_id`, `proc_ver`), 단위마다 하나로 정해지는 컬럼(`lot_floor`: lot마다 층이 하나)을 씁니다.
한 단위 안에서 층 값이 여러 개면 화면에 `단위 N개가 여러 층에 걸쳐 있어 첫 층 기준으로 묶었습니다`가 나옵니다. 이때는 층 비율이 정확히 지켜지지 않으니 단위·층 컬럼을 다시 정하세요.

> 단위는 "무엇을 한 덩어리로 볼까", 층은 "무엇의 비율을 지킬까"입니다.

## 따라 해 보기

### 1단계 — 구성부터 확인 (`--inspect`)

축소하지 않고 단위와 층이 몇 개인지만 봅니다. 단위·층 컬럼을 정할 때 먼저 돌려 보세요.

```bash
python scripts/run_reduce_units.py "데이터 폴더" \
    --unit lot_id,step_id,proc_id,proc_ver \
    --strata step_id,proc_id,proc_ver,lot_floor \
    --inspect
```

```
[A] 파일 1개 · 18,842행 · 컬럼 9개
  단위 4,747개 · 층 조합 360개 · 단위당 행 수 평균 4.0 (최대 7)
  단위가 2개 이하인 드문 층 조합 5개 (모두 최소 1개는 남깁니다)
```

- 층 조합이 단위 수만큼 많다면 층 컬럼이 너무 잘게 나뉜 것입니다. 층 컬럼을 줄여 보세요.
- 폴더 안에서 컬럼 구조가 같은 파일은 하나로 합쳐지고, 구조가 다르면 `[A]`, `[B]`처럼 따로 처리됩니다.

### 2단계 — 축소 실행

비율을 정하면 그 비율로, 정하지 않으면 1%부터 올려 가며(1, 2, 5, 10, 20, 30, 50%) 기준 점수(기본 85점)를 넘는 가장 작은 비율을 찾습니다.

```bash
# 비율 직접 지정: 층마다 단위의 20%를 남김
python scripts/run_reduce_units.py "데이터 폴더" --unit ... --strata ... --ratio 0.2

# 자동 탐색: 90점을 넘는 가장 작은 비율
python scripts/run_reduce_units.py "데이터 폴더" --unit ... --strata ... --target 90
```

```
  비율    1% → 1,359행, 95.9점
원본 18,842행 / 단위 4,747개 → 축소 1,359행 (7.21%) / 단위 360개  ·  0.4초
  종합 유사도 95.9점  (컬럼 비율 93.0 / 조합 비율 100.0 / 단위 크기 94.6)
  · 드문 층 360개는 최소 1개 단위를 남겼습니다
```

비율은 1%인데 실제로는 7.21%가 남았습니다. 층마다 단위를 1%씩 뽑으면 0개가 되는 층이 많아,
`--min-units`(기본 1)만큼은 남기기 때문입니다. 층 조합이 많을수록 실제로 남는 비율이 지정한 비율보다 커집니다.

## 값 종류 줄이기: `--limit`

장비가 120종, 마스크가 80종처럼 값 종류가 너무 많을 때 "6종만 남기기"처럼 줄입니다.

```bash
--limit eqp_id=6,mask_id=6,lot_id=100
```

컬럼 이름은 데이터에 적힌 그대로(대소문자 포함) 씁니다. 실제 데이터가 `EQP_ID`라면 `EQP_ID=6`으로 씁니다.

### 적용 순서 (중요)

1. **`--unit`에 없는 컬럼부터, 적힌 순서대로** (위 예에서 `eqp_id` 다음 `mask_id`)
   - 많이 쓰인 값 N개만 남기고 **나머지 값의 행을 지웁니다.**
   - 그래서 lot은 남아도 그 lot의 이력 중 다른 장비를 거친 행은 빠질 수 있습니다.
2. **`--unit`에 있는 컬럼은 마지막에** (위 예에서 `lot_id`)
   - 1번을 거치고 남은 lot 중에서 100개를 고르고, 그 lot의 단위를 **모두** 남깁니다.
   - 이때는 `--ratio` 축소를 하지 않습니다. 결과 lot이 정확히 100개가 되도록 하기 위해서입니다.
   - 남은 lot이 100개보다 적으면 남은 lot이 모두 결과가 됩니다.

```
  eqp_id: 값 120종 → 6종, 행 18,842 → 1,098 (5.8% 유지)
  mask_id: 값 80종 → 6종, 행 1,098 → 117 (10.7% 유지)
  lot_id: 값 106종 중 100종 선택 (많이 쓰인 순서) → 결과에 100종 남음
  결과 단위 110개 · 층 조합 94개 · 단위당 행 수 평균 1.0 (최대 2)
  단위 컬럼 limit이 있어 --ratio 단위 축소는 하지 않습니다

================================================================
원본 117행 / 단위 116개 → 축소 111행 (94.87%) / 단위 110개  ·  0.0초
  종합 유사도 96.2점  (컬럼 비율 96.9 / 조합 비율 91.8 / 단위 크기 100.0)
```

**여기서 "원본"은 `eqp_id`·`mask_id` 제한을 거친 뒤의 데이터(117행)입니다.** 점수, 값 분포 표, 그래프, `strata_<그룹>.csv` 모두
이 데이터와 축소본을 비교합니다. 처음 읽은 18,842행 전체와 비교한 점수가 아닙니다.

> `--unit` 컬럼(`lot_id`)은 `--limit` 어디에 적어도 마지막에 적용됩니다.
> 하지만 `--unit`에 없는 컬럼끼리는 **적힌 순서대로** 하나씩 거르므로 순서에 따라 결과가 달라집니다.
> 위 데이터에서 `eqp_id=6,mask_id=6`이면 lot이 106개 남고, `mask_id=6,eqp_id=6`이면 116개 남습니다.
> 앞에 적은 컬럼은 전체에서 많이 쓰인 값을, 뒤에 적은 컬럼은 앞에서 남은 행 중 많이 쓰인 값을 고릅니다.
>
> `--unit` 컬럼을 두 개 이상 제한하면(예: `lot_id=100,step_id=5`) **마지막에 적은 컬럼**의 개수만 정확히 맞습니다.
> 앞 컬럼이 줄어들면 화면에 "… 마지막에 적으세요"라고 알려 줍니다.

### 고르는 방법 (`--limit-mode`)

| 값 | 고르는 방법 | 언제 |
|---|---|---|
| `top` (기본) | 행이 많은 값부터 N개 | 주로 쓰이는 장비·lot을 보고 싶을 때 |
| `sample` | 원본 비율을 확률로 삼아 무작위 N개 | 특정 값에 치우치지 않게 하고 싶을 때 |

`--limit-mode`는 `--limit`의 모든 컬럼(장비·마스크·lot)에 똑같이 적용됩니다.

### lot을 제한했을 때 점수 보는 법

`lot_id=100`처럼 제한하면 lot_id 컬럼 자체의 비율 점수는 낮게 나옵니다. 예를 들어 485종 중 100종만 남으면 lot_id 점수가 60점대로 떨어져 종합 점수를 끌어내립니다.
lot_id를 점수에서 빼고 싶으면 `--columns`로 볼 컬럼만 지정하세요.

```bash
--columns step_id,proc_id,proc_ver,lot_floor,eqp_id,mask_id,eqp_floor
```

## 무작위 세트 여러 개 만들기: `--sets`

같은 조건으로 무작위 축소를 여러 번 해서, **기준 점수를 넘는 서로 다른 세트**를 N개 모읍니다.

```bash
python scripts/run_reduce_units.py "데이터 폴더" \
    --unit lot_id,step_id,proc_id,proc_ver \
    --strata step_id,proc_id,proc_ver,lot_floor \
    --limit eqp_id=6,mask_id=6,lot_id=100 \
    --sets 100 --target 85
```

```
  세트 100개 만들기 — 단위 컬럼 limit(lot_id) 값을 세트마다 무작위로 다시 뽑음, 기준 85점, 시도 상한 2000회
    10/100개 완료 (시도 10회)
    ...
  세트 100/100개 저장 · 시도 100회 (기준 미달 0회, 중복 0회)
  점수 95.2 ~ 97.1점 (평균 96.1) · 행 109 ~ 111
```

동작 방식은 이렇습니다.

1. seed를 `--seed`(기본 0)부터 하나씩 올려 가며 다시 축소합니다.
   - lot 제한이 있으면 세트마다 lot을 **무작위(sample)로 다시 뽑습니다.**
     `eqp_id`·`mask_id` 제한 결과는 모든 세트가 같습니다.
   - lot 제한이 없으면 본 실행에서 쓴 비율로 층마다 단위를 무작위로 뽑습니다.
2. 점수가 `--target`보다 낮거나, 이미 나온 세트와 똑같은 세트는 버립니다.
3. N개를 모으거나 `--max-tries`(기본: 세트 수 × 20)에 닿으면 멈춥니다.

멈춘 이유는 화면에 나옵니다.

| 화면 문구 | 뜻 | 해결 |
|---|---|---|
| `대부분 기준 점수 미달입니다` | 무작위로 뽑으면 기준을 넘기 어렵습니다 | `--target`을 낮추거나 `--max-tries`를 늘리기 |
| `서로 다른 세트가 더 나오지 않아 멈췄습니다` | 뽑을 수 있는 조합이 적습니다 | lot 수·비율·세트 수 줄이기 |
| `서로 다른 세트를 만들 수 없습니다` | 비율 100%이거나 lot 제한이 남은 lot 수 이상이라 결과가 하나뿐입니다 | lot 수나 비율 줄이기 |

> 본 결과(`reduced_<그룹>.csv`)는 `--limit-mode`(기본 `top`)로 lot을 고르고, 세트는 항상 무작위(`sample`)로 고릅니다.
> `--limit-mode sample`을 주면 본 결과도 무작위로 고르지만, 장비·마스크 선택까지 무작위가 되므로
> 장비·마스크는 많이 쓰인 순서로 두고 싶다면 기본값(`top`)을 그대로 쓰세요.
>
> 남은 lot이 고를 개수보다 조금만 많으면(예: 106개 중 100개) 세트끼리 lot이 대부분 겹칩니다.
> 세트끼리 충분히 달라야 한다면 남은 lot 수보다 고를 개수를 넉넉히 작게 잡으세요.
>
> 시간은 세트 하나를 만드는 데이터 크기에 비례합니다. 1만 8천 행에서 lot 제한 없이 세트 100개에 약 1분,
> 위처럼 장비·마스크로 117행까지 줄인 뒤에는 약 7초 걸렸습니다. 큰 데이터라면 `--sets 5`로 먼저 시간을 확인하세요.

## 화면 결과 읽는 법

아래는 `--limit eqp_id=20,mask_id=20,lot_id=100`으로 돌린 예입니다.
`--limit`로 행을 거른 경우 "원본"은 거른 뒤의 데이터입니다 (여기서는 18,842행 중 1,064행).

```
원본 1,064행 / 단위 952개 → 축소 417행 (39.19%) / 단위 345개  ·  0.1초
  종합 유사도 87.7점  (컬럼 비율 91.6 / 조합 비율 79.3 / 단위 크기 92.3)
```

**종합 유사도**는 아래 세 점수의 평균입니다 (각 0~100점, 높을수록 원본과 비슷함).
각 점수의 계산 방식과 예시 그림은 [유사도 지표 이해하기](similarity_metrics.md#묶음-단위-축소의-점수-run_reduce_unitspy)를 보세요.

| 점수 | 무엇을 보나 | 낮다면 |
|---|---|---|
| **컬럼 비율** | 컬럼마다 값 비율(예: F1 45%, F2 37%)이 원본과 같은가 | 특정 값이 너무 많거나 적게 남음 |
| **조합 비율** | 층 조합(또는 `--combo`로 정한 조합)의 비율이 같은가 | 드문 조합이 빠졌거나 치우침 |
| **단위 크기** | 단위 하나가 갖는 행 수의 분포가 같은가 | 큰 단위나 작은 단위만 골라짐 |

컬럼별 점수 표의 각 칸은 이런 뜻입니다.

```
    eqp_floor         95.8점  값      3종  최대 비율차  4.19%p  값 커버리지 100.0%
```

- **최대 비율차**: 값 중 원본과 비율 차이가 가장 큰 것의 차이
  - 예: 원본 30%, 축소 34%면 4%p
- **값 커버리지**: 원본에 있던 값 중 축소본에도 남은 값의 비율
  - 100%면 빠진 값이 없다는 뜻입니다.

> 축소본 비율은 행마다 붙은 가중치(`_weight`, 그 행이 원본 몇 행을 대표하는지)를 반영해 계산합니다.

## 그래프 읽는 법

`distribution_<그룹>.png`에는 `--show-dist`로 고른 컬럼(최대 6개)의 막대와 **단위당 행 수** 그래프가 있습니다.
회색은 원본, 파랑은 축소본입니다.

![분포 비교 예시](../images/distribution.png)

> 위 그림은 실제 lot 데이터로 만든 예시입니다. 지금 버전으로 그리면 막대 순서 등 세부 모양이 조금 다를 수 있습니다.

### 컬럼별 막대

- 값마다 원본(회색)과 축소본(파랑)의 비율(%)을 나란히 그립니다.
- 두 막대 길이가 같을수록 그 값의 비율이 잘 유지된 것입니다.
- 오른쪽 아래 `max 0.30%p`는 그 컬럼에서 가장 크게 어긋난 비율 차이입니다.
- 값이 많은 컬럼은 상위 값만 보이고, 나머지는 `(그 외 N종)`으로 묶입니다.

### 단위당 행 수

**단위 하나가 원본에서 몇 행으로 이루어져 있는지**의 분포입니다.

- **가로축**: 단위 하나의 행 수 (예: 1행짜리 단위, 2행짜리 단위, …)
- **세로축**: 그런 단위가 전체 단위 중 차지하는 비율
- **회색 막대**: 원본, **파란 선**: 축소본

예를 들어 lot-공정 단위라면 "이 lot이 이 공정에서 몇 번 기록됐나"의 분포입니다.
파란 선이 회색 막대 윤곽을 잘 따라가면, 축소본에도 행이 많은 단위와 적은 단위가 원본과 같은 비율로 섞여 있다는 뜻입니다.
특정 크기의 단위만 많이 뽑히면 파란 선이 그 자리에서 튀어 오릅니다. 이 차이를 숫자로 나타낸 것이 화면의 **단위 크기** 점수입니다.

## 저장되는 파일

`--out`(기본 `results/`) 아래에 그룹(`A`, `B`, …)마다 저장됩니다.

| 파일 | 내용 |
|---|---|
| `reduced_<그룹>.csv` | 축소본. 첫 컬럼 `_weight`는 그 행이 대표하는 원본 행 수 |
| `report_<그룹>.json` | 점수 상세, 단위·층 수, `--limit` 적용 내용(`value_limits`) |
| `strata_<그룹>.csv` | 층(조합)별 원본·축소 단위 수, 행 수, 비율 차이 |
| `distribution_<그룹>.csv` | 컬럼별 값마다 원본 비율과 축소본 비율 |
| `distribution_<그룹>.png` | 위 그래프 (`--no-plot`이면 만들지 않음) |
| `sets_<그룹>/set_001.csv` … | `--sets`로 만든 세트 (형식은 `reduced_<그룹>.csv`와 같음) |
| `sets_<그룹>.csv` | 세트 요약: 세트 번호, seed, 행 수, 단위 수, 종합·세부 점수, 파일 이름 |

> 같은 `--out`으로 다시 실행하면 파일을 덮어씁니다.
> `--sets`는 시작할 때 이전 실행의 `set_*.csv`를 지웁니다.

## 옵션 전체

| 옵션 | 기본값 | 설명 |
|---|---|---|
| `폴더` | (필수) | 표 파일(`.csv`, `.tsv`, `.txt`)이 있는 폴더 |
| `--unit` | (필수) | 단위 컬럼. 이 값이 같은 행은 통째로 남거나 빠짐 |
| `--strata` | (필수) | 층 컬럼. 이 조합별 단위 비율을 원본과 같게 유지 |
| `--ratio` | 자동 탐색 | 층마다 남길 단위 비율 (0~1, 예: `0.2`) |
| `--target` | 85 | 자동 탐색과 `--sets`의 기준 점수 |
| `--min-units` | 1 | 층마다 최소로 남길 단위 수 |
| `--columns` | 전체 | 비율 점수를 볼 컬럼 |
| `--combo` | `--strata` | 조합 비율을 볼 컬럼 조합 (여러 번 쓸 수 있음) |
| `--limit` | 없음 | 값 종류 줄이기 (예: `eqp_id=6,lot_id=100`) |
| `--limit-mode` | `top` | `top`(많이 쓰인 순서) 또는 `sample`(비율 확률로 무작위) |
| `--sets` | 0 | 기준을 넘는 서로 다른 무작위 세트 개수 |
| `--max-tries` | 세트 수 × 20 | `--sets` 시도 횟수 상한 |
| `--seed` | 0 | 무작위 뽑기 시작값. 같으면 결과도 같음 |
| `--show-dist` | 값 20종 이하 컬럼 | 화면 표와 그래프에 보여 줄 컬럼 |
| `--dist-top` | 10 | 컬럼마다 보여 줄 값 개수 |
| `--no-plot` | 꺼짐 | 그래프를 만들지 않음 |
| `--inspect` | 꺼짐 | 구성만 확인하고 축소하지 않음 |
| `--out` | `results` | 저장 폴더 |

## 자주 겪는 상황

**lot을 100개로 제한했는데 더 적게 나와요.**
- `eqp_id`·`mask_id` 제한을 거친 뒤 남은 lot이 100개보다 적은 경우입니다.
  - 화면의 `lot_id: 값 N종 중 …`에서 N이 남은 lot 수입니다.
- `--unit` 컬럼을 두 개 이상 제한했다면, 개수를 맞출 컬럼을 `--limit` 마지막에 적으세요.

**점수가 계속 기준에 못 미쳐요.**
- 층 조합이 너무 많으면 비율을 맞추기 어렵습니다. `--inspect`로 층 조합 수를 확인하고 `--strata` 컬럼을 줄여 보세요.
- `--limit`로 값 종류를 크게 줄였다면 그 컬럼의 점수가 낮아집니다. `--columns`로 점수에서 빼는 것도 방법입니다.

**"건너뜀 — 데이터에 없는 컬럼입니다"가 나와요.**
- `--unit`·`--strata`·`--limit`에 적은 컬럼이 그 그룹 데이터에 없을 때 나옵니다.
- 컬럼 이름은 대소문자까지 데이터와 같아야 합니다 (`EQP_ID`와 `eqp_id`는 다릅니다).
- 폴더에 구조가 다른 파일이 있으면 그 그룹만 건너뛰고 나머지는 계속 진행합니다.
- `--columns`·`--show-dist`에 없는 컬럼을 적으면 건너뛰지 않습니다. `--columns`는 오류로 멈추고,
  `--show-dist`는 그 컬럼을 조용히 뺍니다. 철자를 먼저 확인하세요.

## 세트별 분포와 세트 간 차이 (T079)

`--sets`로 저장된 각 세트마다 추가 옵션 없이 분포를 저장합니다.
기준 원본은 `--limit`의 장비·마스크 등 행 필터를 적용한 뒤의 데이터입니다.
분포에는 `_weight` 대표 가중치를 적용하므로, CSV 행만 단순히 세어 계산한 비율과 다를 수 있습니다.

| 파일 (`sets_A/` 기준) | 내용 |
|---|---|
| `distributions/set_001.csv` | 원본/세트의 값별 비율·행 수·차이(%p) |
| `distributions/distribution_set_001.png` | 해당 세트의 원본 대비 분포와 단위당 행 수 그림 |
| `comparisons.csv` | 세트 쌍별 평균/최대 TV 거리와 단위 Jaccard 겹침률 |
| `distribution_differences.csv` | 세트 쌍·컬럼별 TV 거리와 최대 비율 차이(%p) |
| `comparison.png` | 평균 TV 거리와 단위 겹침률을 나란히 보는 히트맵 |

- **TV 거리**: 0이면 같은 분포, 1이면 서로 겹치는 값이 없는 분포. 모든 범주로 계산합니다.
  `--dist-top`은 분포 표/그림만 줄이며 거리 계산에는 영향을 주지 않습니다.
  평균 TV는 `--columns`(없으면 기존 전체 비교 컬럼)의 단순 평균입니다.
  ID 컬럼이 많으면 평균에 영향이 크므로 `--columns`로 관심 컬럼을 지정하거나 컬럼별 파일을 확인하세요.
- **Jaccard 겹침률**: 두 세트의 선택 단위 교집합 / 합집합. 0이면 겹치지 않고 1이면 같습니다.
  lot_id 하나가 아니라 `--unit`에 적은 전체 컬럼 조합을 기준으로 합니다.
- 분포 차이는 작지만 겹침률도 낮으면, 비슷한 분포를 유지하며 다른 단위를 선택한 것입니다.
- `--no-plot`은 모든 추가 PNG를 생략하고 CSV는 저장합니다.
- 비교 그림은 첫 40세트까지만 표시합니다. CSV에는 전체 세트 쌍을 저장합니다.
- 비교 히트맵의 색은 **그 그림 안의 값 범위**에 맞춰 칠합니다. 0~1 절대 눈금이 아닙니다.
  같은 기준을 통과한 세트끼리는 값이 비슷해서, 0~1로 고정하면 전부 같은 색으로 보이기 때문입니다.
  색이 진하다고 차이가 큰 것이 아니므로 실제 크기는 색 막대의 눈금이나 CSV로 확인하세요.
  대각선(자기 자신)은 회색으로 비우고, 10세트 이하이면 칸마다 값을 적습니다.
- 0·1세트이면 비교 CSV에는 헤더만 저장하고 쌍 비교 그림은 만들지 않습니다.
- 세트별 그림 때문에 실행 시간이 늘어납니다. 우선 `--sets 5`로 확인하거나 `--no-plot`으로 CSV만 확인하세요.
- 비교 쌍 수는 N(N-1)/2입니다. 100세트는 4,950쌍이므로 큰 세트 수에서는 시간·메모리가 늘어납니다.
- 다시 실행하면 이전 세트별 보고서/그림도 정리합니다. 기존 데이터 세트 CSV의 저장 위치는 그대로입니다.
