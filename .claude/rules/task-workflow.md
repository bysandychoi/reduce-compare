# 태스크 진행 규칙

## 시작
- 한 번에 하나의 태스크만 in_progress로 둔다. 이미 in_progress인 태스크가 있으면 그것부터 이어서 하거나, 사용자에게 확인한 뒤 `blocked`/`todo`로 돌린다.
- 무엇을 할지 사용자가 정하지 않았으면 `python3 backlog.py next` 결과를 보여 주고 고르게 한다. 임의로 고르지 않는다.
- 선택한 태스크를 `python3 backlog.py status <ID> in_progress`로 바꾼 뒤, 바로 **task-briefer**를 호출해 `docs/tasks/<ID>.md`를 만든다.
- 브리핑을 읽고 "해야 할 일"과 "완료 기준"을 사용자에게 3줄 이내로 확인시킨 뒤 구현한다.

## 진행 중
- `docs/tasks/<ID>.md`의 "해야 할 일" 체크박스를 끝날 때마다 체크한다.
- 태스크 범위를 벗어나는 일이 필요하면 직접 하지 말고 `python3 backlog.py add ...`로 새 태스크를 만든다 (30분 이하, 의존 관계 지정).
- 30분 안에 끝나지 않을 것 같으면 멈추고 태스크를 나눈다 (`update`로 범위 축소 + `add`로 나머지).
- 막히면 `status <ID> blocked`로 바꾸고 이유를 사용자에게 알린다.

## 리뷰
- 파일을 만들거나 고쳐서 한 덩어리의 작업이 끝날 때마다 **adversarial-reviewer**를 호출한다 (최소한 done 직전 한 번).
- 판정이 `재작업 필요`면 치명·중요 지적을 모두 고치고 다시 리뷰를 요청한다.
- 지적에 동의하지 않으면 무시하지 말고 `docs/tasks/<ID>.review.md` 맨 아래에 `### 작성자 의견` 절을 달아 근거를 적은 뒤 다시 리뷰를 요청한다. 리뷰어가 받아들여 PASS를 줘야 끝난다.
- 리뷰를 받은 뒤 파일을 또 고치면 그 리뷰는 무효다 (훅이 파일 수정 시각으로 확인한다).

## 끝
- 완료 기준을 모두 확인하고 리뷰 PASS를 받은 뒤에만 `python3 backlog.py status <ID> done`을 실행한다.
- done 처리가 훅에 의해 되돌려지면 메시지의 원인(리뷰, lint, build, 브랜치)을 해결한 뒤 다시 실행한다.
- 커밋·push는 훅이 한다. 직접 `git commit`/`git push`를 하지 않는다.
